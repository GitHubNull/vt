## 1. 项目速览

- **VibeType（码语）**：面向程序员的隐私优先 AI 语音输入法——本地离线 ASR + 编程口令 + 场景感知 + AI 后处理。
- **技术栈**：Tauri 2（Rust + tokio）+ Vue 3 + TypeScript + Vite 6 + PrimeVue 4 + Pinia；前端包管理 **pnpm**；权威清单见 `doc/tech/02-技术栈与依赖`。
- **仓库**：`github.com/GitHubNull/vt`（公共仓库，2026-10-11 起；全部提交历史与文档对外可见）。
- **产品原则（不可违背，AGENTS.md 3.2）**：本地优先 / 零打扰 / 结果可预期 / 安全第一（**终端场景默认禁止自动回车，宁可漏转不可错转**）/ 隐私优先。
- **已决策移除**：音视频转录（F-FILE-01~03），不要重新引入。

## 2. 权威文档与执行方式

1. **需求以 PRD 为准**（`doc/prd/`，功能编号如 F-CODE-01、F-AI-01；PRD 写"做什么"，不写实现）。
2. **执行入口**：`doc/roadmap/v0.5-beta.md` 任务分组清单 → 每个任务有 SPEC（`doc/specs/v0.5/T-5xx-*.md`），**逐条满足 SPEC 中的验收标准**，技术方案以 `doc/tech/` 为准。
3. PRD / SPEC 与实现冲突时，**先停下修改文档并说明原因，再改实现**。
4. 技术文档 05（核心管线）、08（数据安全）、09（跨平台）与 v0.1 实现有出入时，以实际代码为准并回写文档（上游就是这么做的）。

## 3. 构建与运行环境（重要，踩过的坑）

### 3.1 cargo 环境变量（任何 cargo 命令之前必须先 export）

```bash
export CARGO_HOME=/home/wgh/dev/cross_platform_app/vt/tmp/cargo-home
export PKG_CONFIG_PATH=/home/wgh/dev/cross_platform_app/vt/tmp/alsa-prefix/lib/pkgconfig
export LIBCLANG_PATH=/home/wgh/dev/cross_platform_app/vt/tmp/clang-prefix/usr/lib/llvm-19/lib
export SHERPA_LIB_PATH=/home/wgh/dev/cross_platform_app/vt/tmp/sherpa-libs
```

无 sudo 权限。alsa/clang/sherpa 依赖均已解压在 `tmp/` 下（见上路径）。

### 3.2 发布版二进制必须用 `pnpm tauri build`

**不要用 `cargo build --release` 出包**：那样编出的二进制设置窗报 "Could not connect to localhost: Connection refused"（缺 Tauri CLI 注入的前端资源/环境）。任何要给用户跑的构建一律 `pnpm tauri build`。
Linux 本地 AppImage 打包有环境问题（linuxdeploy 偶发失败），属环境噪声，忽略；deb/rpm 正常。

### 3.3 验证命令（提交前必过）

```bash
pnpm lint && pnpm typecheck && pnpm test
cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test
```

Windows-only 代码（`src-tauri/src/platform/` 下 windows 模块）本机无 MSVC，用 `tmp/win-check/` shim crate（gitignored，已存在）做交叉检查：`cargo clippy --target x86_64-pc-windows-msvc`。注意 windows-sys 0.59 缺 MMDevice COM 接口，`platform/volume.rs` 里是手写 vtable，改 windows 平台代码时参考它。

### 3.4 其他环境事实

- git push **只走 SSH**（https TLS 在本机损坏）；force-push 被服务端拒绝；重打 tag = 先删远端 tag 再重推。
- gh CLI 已认证（用户 GitHubNull）。
- 外网下载慢：`curl` 等加 `-x http://127.0.0.1:7890`。
- 用户的功能测试机在**另一台 Windows 机器**上，优先保证 Windows 产物与 Windows 路径正确。
- 用户数据目录：Linux 上配置在 `~/.config/com.vibetype.app/`（config.json + .bak）；`~/.local/share/com.vibetype.app/` 是数据/日志/模型。

## 4. 协作规则（沿用，勿违反）

- 提交信息中文，格式 `类型: 简述`（feat/fix/docs/refactor/test/chore）；**单个提交只做一件事；文档变更与代码变更分开提交**。
- 代码与日志中不得写入密钥、令牌、用户语音文本原文（日志已做脱敏）。
- 用户可见文案集中在 i18n 资源（`src/i18n/locales/zh-CN.ts` 等），不散落逻辑里。
- 产物/临时文件不进 git：`tmp/`、模型文件、数据目录均已 gitignore。
- **UI 修复流程**：先在本地 `pnpm tauri build`（或 dev）跑真实应用给用户确认截图，攒批一次发版；**用户确认前不推 GitHub**。发版 = 语义化 tag（下一个 tag 是 **v0.1.13**）+ `git push` 触发 GitHub Actions（`.github/workflows/release.yml`，tag `v*.*.*` 触发，自动出 Release 与各平台安装包）。
- 版本号文件约定：Cargo.toml / package.json 保持 0.1.0（tag 才是发布计数，见 NFR-P-09），**不要**为了发版去改版本号字段。
- 验收不符项先定性（缺陷 / 设计如此 / 平台限制）：缺陷→修；设计如此→改文档对齐；平台限制→写入验收手册 §7 已知限制 + 路线图立项，不要硬修。
- 并行子代理协作时按文件所有权严格划分，避免冲突。
