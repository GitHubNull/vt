# 第 3 章 功能需求详述

> 本章按模块描述功能。每个功能包含：用户故事、功能说明、业务规则、交互要点、异常与边界、验收标准。只描述产品行为，不规定实现方式。

## 3.1 语音输入核心

### 3.1.1 全局快捷键录音（F-INPUT-01、F-INPUT-02）

**用户故事**
- 作为程序员，我希望在任何应用里按一个键就能开始说话，说完文字自动出现在光标处，这样我不用切换窗口。
- 作为程序员，我希望默认快捷键不和 IDE 冲突，这样我装完就能用，不用先去改设置。

**功能说明**
- 提供一个全局“录音快捷键”，用于开始 / 结束录音，此快捷键只做转录、不做 AI 处理（AI 处理由模板快捷键触发，见 3.5）。
- 支持两种触发方式（“通用 › 输入与录音 › 按住说话”开关）：
  - **按住说话（默认开启）**：按住快捷键录音，松开即结束；
  - **切换模式**：按一次开始，再按一次结束。

**业务规则**
1. **默认快捷键**：Windows / Linux 为“右 Alt”，macOS 为“右 Option”。
   - 理由：参考原型默认使用 F2，但 F2 是主流 IDE 的“重命名符号”快捷键，与程序员高频操作冲突；右侧修饰键单独按下几乎不被任何开发工具占用，且适合“按住说话”。
2. 可设置的快捷键类型：单个功能键（F1–F24）、单个左 / 右修饰键（左右 Alt / Ctrl / Shift / Option / Command 区分左右）、组合键（如 Ctrl+Shift+Space）、鼠标侧键（前进键 / 后退键）。
3. 单独修饰键作为快捷键时，若用户按下该键后又按了其他键（例如正常使用右 Alt 组合键），则不触发录音，保证原组合键可正常使用。
4. 按住说话模式下，按住时间小于 0.3 秒视为误触，不开始录音、不打扰用户。
5. 单次录音最长 5 分钟（可在“通用”中调整为 1–10 分钟）；到达上限前 10 秒悬浮球倒计时提示，到达上限自动结束并正常处理。
6. 录音过程中按 Esc（取消快捷键，可配置）放弃本次录音，不上屏、不计入统计（F-INPUT-07）。
7. 设置快捷键时须进行冲突检测（F-SYS-03）：与本产品其他快捷键重复时禁止保存；与已知常用软件快捷键冲突时给出提示但允许保存。

**验收标准**
- 在 IDE、终端、浏览器、即时通讯软件中，按住默认快捷键说话、松开后文字均能在光标处上屏。
- 正常使用“右 Alt + 其他键”组合时不会误触发录音。
- 按下 Esc 后本次录音被丢弃，光标处无任何输入。
- 将快捷键设置为与“模板快捷键”相同的键时，界面提示冲突且无法保存。

### 3.1.2 本地离线识别（F-INPUT-03）

**功能说明**
- 默认使用本地语音识别模型完成识别，录音数据不离开用户电脑。
- 支持中文、英文以及中英混说；支持在“模型管理”中切换模型（见 3.8.7）。

**业务规则**
1. 未下载任何模型时，按下录音快捷键应弹出提示“尚未安装语音识别模型”，并提供“前往下载”按钮。
2. 识别过程中不得请求网络。
3. 识别结果进入“文本处理流程”（见 3.1.5）后再上屏。

**验收标准**
- 断开网络后，语音输入功能完整可用。
- 在未下载模型的状态下触发录音，出现引导下载的提示。

### 3.1.3 光标处上屏与无焦点兜底（F-INPUT-04、F-INPUT-09）

**功能说明**
- 识别结果输入到录音开始时的焦点位置。
- 支持两种上屏方式（“通用 › 文本输出 › 使用复制粘贴输入”）：
  - **复制粘贴输入（默认开启）**：速度快、稳定，适合长文本；
  - **模拟键入**：逐字输入，适用于不支持粘贴的输入框。

**业务规则**
1. 使用复制粘贴输入时，上屏完成后默认**恢复用户原有剪贴板内容**；仅当“保留识别文本到剪贴板”开启时，剪贴板保留识别结果。
2. 若录音开始到上屏期间用户切换了窗口，结果仍输入到**录音开始时**的窗口；若该窗口已关闭，按无焦点兜底处理。
3. **无焦点兜底**：当前没有可输入的位置时，结果写入剪贴板，悬浮球提示“已复制到剪贴板”，并写入历史记录。
4. 终端场景下的上屏须遵守终端安全保护（见 3.2.5）。

**验收标准**
- 剪贴板中原有内容在语音上屏后仍可正常粘贴（默认设置下）。
- 在桌面（无输入框）触发语音输入，结果出现在剪贴板并有提示。

### 3.1.4 语音输入小窗（F-INPUT-06）

参考截图：`PixPin_2026-10-09_21-38-03.png`

**功能说明**
- 小窗是产品的轻量主界面，包含：
  - 标题栏：“语音输入”，最小化、关闭按钮（关闭 = 隐藏到托盘，不退出产品）；
  - 中央圆形麦克风按钮：点击开始 / 结束录音；
  - 状态提示文案：空闲时显示“按 右Alt 或点击开始”（快捷键名称随设置变化）；
  - 当前场景标签：如“编码场景 · VS Code”；
  - 最近一次识别结果（单行省略），点击可复制；
  - 底部两个按钮：**历史记录**、**设置**（齿轮）。设置按钮右上角红点表示“有新版本”或“有需要处理的问题”（如模型缺失、权限缺失）。

**业务规则**
1. 点击小窗麦克风录音时，结果上屏到**打开小窗之前**最后一个获得焦点的输入位置；若无法确定，按无焦点兜底处理。
2. 小窗默认置顶可关闭（右键菜单“窗口置顶”）。
3. 小窗位置、是否显示在下次启动时保持。

**验收标准**
- 小窗中显示的快捷键名称与“通用”中设置的一致。
- 存在新版本时，设置按钮出现红点，进入“关于”后红点消失。

### 3.1.5 文本处理流程

识别结果在上屏前依次经过以下处理，每一步均可由用户在设置中关闭：

| 顺序 | 处理步骤 | 说明 | 设置位置 |
| --- | --- | --- | --- |
| 1 | 语气词过滤 | 删除“嗯、啊、呃、那个那个”等 | 通用 › 文本输出 |
| 2 | 专有名词校正 | 将识别出的近似读音校正为标准写法 | 词典 › 专有名词、编程 › 技术词库 |
| 3 | 替换词典 | 精确匹配“错误词”替换为“正确词” | 词典 › 替换词典 |
| 4 | 编程口令解析 | 命名风格、符号、按键口令 | 编程 › 编程口令 |
| 5 | 智能数字转换 | “一百二十” → “120” | 通用 › 文本输出 |
| 6 | 标点与空格规范 | 全半角、中英文间空格、结尾标点 | 编程 › 场景规则、通用 › 文本输出 |
| 7 | 繁简转换 | 输出繁体中文 | 通用 › 文本输出 |
| 8 | AI 处理（可选） | 仅在使用 AI 模板时执行 | AI › 提示词管理 |

**业务规则**
- 用户个人设置的优先级高于技术词库：专有名词（用户手动添加）> 项目导入术语 > 技术词库。
- 替换词典的“正确词”不再参与后续的专有名词校正与口令解析，避免二次改写。

### 3.1.6 录音悬浮球（F-INPUT-05）

**功能说明**
- 录音开始时出现，展示：音量波形动效、录音时长、当前模式（“纯转录”或模板名称，如“结构化 Prompt”）。
- 状态：录音中 → 识别中 → AI 处理中（仅模板）→ 完成 / 失败，详见第 4 章录音状态设计。

**业务规则**
1. 可在“通用 › 输入与录音 › 悬浮球”关闭；关闭后仍保留托盘图标状态变化与提示音（如开启）。
2. 位置可选：跟随光标附近（默认）/ 屏幕底部居中 / 固定在用户拖动后的位置。
3. 悬浮球不得抢占输入焦点。
4. 点击悬浮球 = 结束录音；悬浮球上的“×”= 取消录音。

**验收标准**
- 录音期间焦点始终保持在原输入框，键盘输入不受影响。
- 使用模板快捷键时，悬浮球显示该模板名称。

### 3.1.7 历史记录（F-INPUT-08）

**功能说明**
- 保存最近的语音输入结果，每条显示：时间、来源应用、场景、模式（纯转录 / 模板名）、最终文本；可展开查看“原始识别文本”与“AI 处理结果”对比。
- 操作：复制、再次上屏、用其他模板重新处理、删除、加入替换词典（选中错误片段，一键创建替换规则）。

**业务规则**
1. 默认保留 7 天、最多 500 条，可在“通用 › 隐私与安全”中调整为：不保存 / 1 天 / 7 天 / 30 天。
2. 历史记录仅保存在本地，支持一键清空。
3. 若开启了敏感信息检测，命中敏感信息的条目以掩码形式保存。

**验收标准**
- 选择“不保存”后，新的语音输入不出现在历史中。
- 在历史中选中一段错误文字并“加入替换词典”，词典中出现对应规则。

## 3.2 编程增强（一级模块“编程”）

### 3.2.1 场景规则（F-CODE-01）

**用户故事**
- 作为程序员，我希望在 IDE 里输出半角符号、不带句号，在飞书里输出中文标点，在终端里绝不自动回车，而不用每次手动切换。

**功能说明**
- 产品根据当前前台应用（以及可选的窗口标题关键字）自动匹配“场景”，每个场景有一组输出规则。
- 内置五个场景：

| 场景 | 默认匹配的应用类型 | 默认规则 |
| --- | --- | --- |
| 编码场景 | IDE、代码编辑器 | 半角标点；删除结尾标点；编程口令开启；中英文间不自动加空格 |
| 终端场景 | 各类终端模拟器、IDE 内置终端 | 半角标点；删除结尾标点；编程口令开启；**禁止自动回车**；危险命令提醒 |
| AI 对话场景 | IDE 的 AI 对话面板、命令行智能体、浏览器中的大模型对话页 | 保留中文标点；中英文间自动加空格；可设置默认使用“结构化 Prompt”模板（默认关闭） |
| 文档沟通场景 | 即时通讯、文档工具、Markdown 编辑器、邮件 | 中文全角标点；中英文间自动加空格；保留结尾标点 |
| 默认场景 | 未匹配到任何规则的应用 | 跟随“通用 › 文本输出”设置 |

**页面设计**
- 中栏二级导航“场景规则”，内容区为场景卡片列表（样式同 AI 供应商卡片，可折叠）。
- 展开场景卡片后可编辑：
  - 场景名称、图标颜色；
  - 匹配应用列表：从“正在运行的应用”中选择，或手动输入应用名称；可附加“窗口标题包含”关键字（用于区分浏览器中的不同网页，例如标题包含“Pull Request”）；
  - 输出规则：标点风格（全角 / 半角 / 跟随识别）、结尾标点（保留 / 删除）、中英文间空格（自动添加 / 不处理）、编程口令（开 / 关）、自动回车（禁止 / 允许）、默认 AI 模板（无 / 指定模板）。
- 右上角“添加”按钮新建自定义场景；内置场景可编辑、不可删除，可“恢复默认”。
- 列表顶部显示“当前识别到：VS Code → 编码场景”，便于用户确认规则是否生效。

**业务规则**
1. 匹配优先级：带“窗口标题关键字”的规则 > 仅按应用匹配的规则 > 默认场景；同级按列表顺序，支持拖动排序。
2. 场景在**录音开始时**确定，录音期间切换窗口不改变本次场景。
3. 用户可在托盘菜单中临时“锁定场景”（例如始终使用编码场景），直到解除锁定。

**验收标准**
- 在 IDE 中口述“这个函数返回空值。”上屏结果不带句号、标点为半角；同一句话在即时通讯中上屏为带全角句号的句子。
- 新建“窗口标题包含 Pull Request → 文档沟通场景”规则后，在浏览器的 PR 页面中生效，其他网页不受影响。

### 3.2.2 命名风格口令（F-CODE-02）

**用户故事**
- 作为程序员，我希望说“驼峰 user name”就得到 userName，这样我可以口述变量名、函数名。

**功能说明**
- 以“口令词 + 内容”的形式说出，产品将内容转换为对应命名风格：

| 口令词（可任选其一） | 风格 | 用户说 | 上屏 |
| --- | --- | --- | --- |
| 驼峰 / 小驼峰 | 小驼峰 | 驼峰 user name | userName |
| 大驼峰 / 帕斯卡 | 大驼峰 | 大驼峰 order service | OrderService |
| 蛇形 / 下划线 | 蛇形 | 蛇形 max retry count | max_retry_count |
| 常量 / 全大写 | 大写蛇形 | 常量 max retry count | MAX_RETRY_COUNT |
| 烤串 / 短横线 | 短横线 | 烤串 main content | main-content |
| 点分 | 点分 | 点分 com example demo | com.example.demo |
| 路径 | 斜杠分隔 | 路径 src components button | src/components/button |
| 全小写 / 连写 | 全小写无分隔 | 连写 user name | username |

**业务规则**
1. 口令只在“编程口令”开启的场景中生效（编码场景、终端场景默认开启）。
2. 口令作用范围：口令词之后、直到出现停顿（约 0.6 秒）或下一个口令词 / 中文标点为止的英文单词。
3. 口令内容为中文时（如“驼峰 用户名”），若已配置 AI 供应商且开启“中文命名翻译”，则先翻译为英文再转换（得到 userName）；否则保留原文并提示“中文命名需要启用 AI”。
4. 内容中的专有名词保持标准写法的大小写规则，例如“大驼峰 http client”在专有名词中有 HTTP 时输出 HTTPClient（可在口令设置中选择“缩写词按普通单词处理”，输出 HttpClient）。
5. 用户可在“编程 › 编程口令”中修改口令词、增加同义口令词、关闭某个口令。
6. **原文转义**：在口令词前说“原文”，口令词作为普通文字输出（例如“原文 驼峰”输出“驼峰”）。

**验收标准**
- 表中所有示例在编码场景中输出正确。
- 在文档沟通场景（口令默认关闭）中说“驼峰 user name”，输出原文“驼峰 user name”。

### 3.2.3 符号口令（F-CODE-03）

**功能说明**
- 在编程口令开启的场景中，以下中文说法转为符号（用户可增删改）：

| 用户说 | 输出 | 用户说 | 输出 |
| --- | --- | --- | --- |
| 左括号 / 右括号 | ( / ) | 左方括号 / 右方括号 | [ / ] |
| 左花括号 / 右花括号 | { / } | 左尖括号 / 右尖括号 | < / > |
| 一对括号 | () | 一对花括号 | {} |
| 箭头 | -> | 胖箭头 | => |
| 等号 | = | 双等号 / 三等号 | == / === |
| 不等于 | != | 大于等于 / 小于等于 | >= / <= |
| 与与 / 逻辑与 | && | 或或 / 逻辑或 | \|\| |
| 管道 / 竖线 | \| | 反引号 | ` |
| 分号 / 冒号 / 逗号 / 点 | ; / : / , / . | 双冒号 | :: |
| 下划线 / 短横线 | _ / - | 斜杠 / 反斜杠 | / / \\ |
| 井号 / at 符号 / 美元符 | # / @ / $ | 波浪号 / 百分号 / 星号 | ~ / % / * |
| 单引号 / 双引号 | ' / " | 加加 / 减减 | ++ / -- |

**业务规则**
1. 符号口令需作为独立的词出现，避免误伤正常语句（例如“这个点子很好”中的“点”不转换）。判定规则：前后有停顿，或前后紧邻英文单词 / 数字 / 其他符号口令。
2. 识别不确定时以“不转换”为准——宁可漏转，不可错转。
3. 符号与英文单词之间不自动添加空格；用户可说“空格”插入一个空格。

**验收标准**
- 编码场景说“user 点 name”输出 user.name；说“user 点 驼峰 get name 一对括号”输出 user.getName()。
- 说“这个点子很好”时不发生符号转换。

### 3.2.4 按键口令（F-CODE-04）

**功能说明**
- 句子结尾单独说出以下口令，执行对应按键：

| 口令 | 动作 | 默认状态 |
| --- | --- | --- |
| 回车 / 发送 | 按下回车键 | 开启（终端场景下受安全保护约束） |
| 换行 | 插入换行（不发送），即 Shift+回车 | 开启 |
| 缩进 / 制表符 | Tab | 开启 |
| 退格 | 删除前一个字符 | 开启 |
| 删除上一句 | 撤销本产品上一次上屏的内容 | 开启 |
| 撤销 | Ctrl/Command + Z | 关闭（默认关闭，避免误操作） |
| 全选 | Ctrl/Command + A | 关闭 |

**业务规则**
1. 按键口令仅在**整段语音的开头或结尾**、且前后有明显停顿时生效。
2. “删除上一句”只删除本产品上一次上屏的文本，不影响用户手动输入的内容；只能回退一次。
3. 替换词典中的“正确词”也可设置为按键动作（参考原型中“回车”词条），二者效果相同；按键口令是内置的、开箱即用的版本。

**验收标准**
- 在即时通讯中说“今天的构建已经修好了 发送”，消息被发送。
- 说“删除上一句”后，上一次语音上屏的文字被删除，其余内容不变。

### 3.2.5 终端安全保护（F-CODE-05）

**用户故事**
- 作为程序员，我担心语音识别错误时命令被直接执行，我希望在终端里语音输入只负责“打字”，执行永远由我自己按回车。

**业务规则**
1. 终端场景下：
   - 上屏文本中的换行符被替换为空格（多行内容除外，见第 3 条）；
   - “回车 / 发送”按键口令与替换词典中的回车动作**默认不生效**，悬浮球提示“终端中已阻止自动回车”；
   - 用户可在场景规则中手动允许自动回车，开启时需二次确认，并在悬浮球上持续显示“自动回车已开启”标记。
2. **危险命令提醒**：上屏的文本若包含高风险命令特征（如递归强制删除、磁盘格式化、强制推送、清空数据库、修改系统权限、管道下载并执行脚本等），悬浮球以醒目颜色提示“检测到高风险命令，请确认后再执行”。提醒不阻止上屏，仅提示；规则清单可在设置中查看与扩展。
3. 多行文本（如通过 AI 生成的多行脚本）在终端中上屏前弹出确认：“将输入 N 行内容，是否继续？”。

**验收标准**
- 在终端中说“git status 回车”，只输入“git status”，命令不执行，并有提示。
- 在终端中上屏包含递归强制删除根目录特征的文本时，出现高风险提醒。

**验收标准**

4. 英文句子（整句为英文）始终使用半角标点，句首字母大写可在设置中关闭。

**验收标准**

### 3.5.2 编程向内置模板（F-AI-03）

参考原型中的内置模板为通用娱乐向（纠错模式、祖安模式、和平使者、恋爱大师、翻译模式）。本产品保留“纠错模式”与“翻译”能力，其余替换为编程向模板：

| 模板名称 | 适用场景 | 用户口述示例 | 期望输出特征 |
| --- | --- | --- | --- |
| 纠错模式 | 全部 | “把超时改成十秒，啊不对，改成三十秒” | 识别“啊不对、算了、改成、我的意思是”等修正指令，删除被否定的内容，只输出最终意图；不回答、不扩写 |
| 结构化 Prompt | AI 对话 | 零散口述一个需求 | 整理为“背景 / 目标 / 约束 / 验收标准”结构的提示词，保留所有技术细节，不臆造需求 |
| Commit 信息 | 终端、IDE | “修了登录页在 Safari 下按钮点不了的问题” | 输出规范格式的提交信息：类型、范围、简述，必要时附正文 |
| Code Review 评论 | 文档沟通（代码托管平台） | 口述评审意见 | 礼貌、具体、可执行；包含问题、原因、建议 |
| 命名助手 | 编码 | “一个判断用户是否有管理员权限的方法” | 给出 1 个首选标识符（遵循当前语言惯例），不输出解释 |

| 技术翻译 | 全部 | 中文口述 | 地道的英文技术表达，术语、代码、链接保持原样；支持反向 |
| 终端命令 | 终端 | “查看八零八零端口被谁占用” | 输出一条对应当前操作系统的命令，**只上屏不执行**，高风险命令附带提醒 |

## 3.6 MCP 服务（AI › MCP 服务，F-AI-09、F-AI-10、F-AI-11）

参考截图：`PixPin_2026-10-09_21-34-32.png`

**用户故事**
- 作为使用 AI 编程智能体的程序员，我希望智能体在需要我确认时能弹出录音让我语音回答，而不必回到键盘。

**页面设计**
- 标题“MCP 服务”，右上角状态徽标：“运行中（端口：36058）”（绿色）/“已停止”（灰色）/“启动失败：端口被占用”（红色）。
- 卡片“启用 MCP 服务”：说明“供 AI Agent 调用本产品的语音能力”，链接“查看使用教程”，右侧开关。
- 服务地址只读框（如本机地址 + 端口 + 路径）与“复制”按钮。
- 新增（相对原型）：
  - **端口设置**：默认 36058，可修改；端口被占用时提示并提供“自动选择可用端口”；
  - **访问令牌**：可开启“需要访问令牌”，显示令牌（默认掩码）、复制、重新生成；
  - **能力清单**：以开关列表展示对外提供的能力：
    - 语音提问：智能体发起一个问题，本产品弹出带问题文本的录音卡片，用户语音回答后将文字返回给智能体；用户可拒绝或超时（默认 60 秒）；
    - 查询 / 添加专有名词：智能体可读取术语，或建议新增术语（新增需用户在弹窗中确认）；
  - **客户端配置助手**：选择常见的智能体客户端，一键复制对应的连接配置说明；
  - **调用记录**：最近 100 次调用的时间、调用方、能力、结果（成功 / 失败 / 用户拒绝），不记录语音内容正文。

**业务规则**
1. MCP 服务默认**关闭**，用户开启后才运行；仅监听本机，不接受来自其他设备的连接。
2. “语音提问”每次都必须由用户主动按下录音才会采集声音，智能体不能静默开启麦克风。
3. 关闭能力开关后，对应能力对智能体不可见。
4. 产品退出时服务停止；开机自启且服务开启时自动恢复。

**验收标准**
- 开启服务后状态显示“运行中”并显示端口；将端口改为已被占用的端口时显示错误并可一键改用可用端口。
- 智能体发起语音提问时出现录音卡片，用户不操作则 60 秒后返回“用户未响应”。

- 操作：下载、暂停、删除、设为默认；下载源可选（官方源 / 镜像源），**默认镜像源**（国内可直连），两源下载后均做 SHA-256 完整性校验，校验值以内置元数据为准。

- 使用中的模型不可删除；下载失败显示原因与重试按钮。

**模型保存位置**
- 路径只读框 + “更改”按钮。更改时提示“是否将已下载模型迁移到新位置？”；新位置空间不足时禁止并提示。
- **默认位置为软件安装目录下的语义化子目录 `models/`**（如 `…/VibeType/models/`）；安装目录不可写（如系统目录、只读挂载）时自动回退到系统数据目录下的 `models/`，并在界面上注明实际位置。

**验收标准**
- 切换默认模型后，下一次语音输入使用新模型。
- 更改模型保存位置并选择迁移后，模型在新路径可用。
- 默认下载源（镜像源）可完成下载且 SHA-256 校验通过；切换官方源同样可下载。
- 下载过程中显示实时速度；杀掉应用进程后重新点击下载，从断点继续而非重新开始。
- 配置代理后模型下载经代理生效（可通过代理日志或抓包验证），留空恢复直连。
- 全新安装后模型默认落在安装目录下 `models/` 子目录（不可写安装目录除外，回退数据目录并注明）。

## 3.13 日志（一级模块“日志”，F-LOG-01 ~ F-LOG-03）

**用户故事**
- 作为内测用户 / 排障者，我希望在应用内直接查看、搜索、过滤日志（支持正则与大小写开关），快速定位问题，而不必手动到日志目录翻文件。
- 作为关注隐私的用户，我希望日志除了文本文件外还能记到本地数据库里方便检索，并且记录哪些目标可以由我自己配置。

**页面设计**
- 独立一级导航“日志”，与“关于”平级，不并入“关于”模块。
- 内容区自上而下：
  1. **记录目标**卡片：两个开关——“记录到文本文件”“记录到本地数据库”（默认均开）。至少保留一项开启；尝试全部关闭时给出提示并拒绝保存。
  2. **搜索与过滤**栏：关键词输入框（默认匹配模式）、“正则表达式”开关、“大小写敏感”开关、级别多选（DEBUG / INFO / WARN / ERROR）、时间范围（起止时间）。
  3. **日志列表**：按时间倒序展示匹配结果（单页最多 200 条），每行包含时间、级别、模块（target）、内容；日志语法高亮（时间 / 级别 / 模块 / 正文以不同颜色区分），命中关键词的部分高亮标出。
  4. 结果底部：“导出搜索结果”按钮——按当前搜索条件导出匹配日志（带系统信息头、自动脱敏）。
- 未开启“记录到本地数据库”时：搜索与过滤区禁用，展示说明文案（开启数据库记录后可使用搜索）；记录目标配置仍可修改。

**业务规则**
1. 日志可同时异步记录到两类目标：按天滚动的文本文件、本地数据库；两类目标默认全部开启，至少选择一项。
2. 文本文件与数据库中的日志均最多保留 7 天（NFR 5.7）；写入均为异步，不得阻塞语音输入主链路。
3. 搜索模式默认为关键词匹配；“正则表达式”开关打开时按正则匹配，表达式非法时提示且不执行搜索。
4. “大小写敏感”开关默认关闭（不区分大小写匹配）。
5. 数据库记录关闭期间产生的日志不进入数据库，因此对这段时间执行搜索没有结果；重新开启后只影响之后产生的日志。
6. 搜索结果与导出内容遵守 NFR-S-02：日志在写入前已完成脱敏，界面与导出文件不得出现 API Key、访问令牌、识别文本、剪贴板内容。
7. 日志级别、搜索条件等界面状态刷新页面后恢复默认。

**验收标准**
- 输入关键词后能过滤出包含该词的日志，命中部分在列表中高亮显示。
- 打开“正则表达式”开关后按正则过滤生效；输入非法正则（如 `[`）时给出提示，列表内容不变。
- “大小写敏感”开关关闭时搜索 `error` 能命中 `ERROR` 级别的日志；打开后仅命中完全一致的文本。
- 关闭“记录到本地数据库”并保存后，搜索区变为不可用并显示说明；重新开启后搜索恢复可用。
- 尝试同时关闭两种记录目标时无法保存，并提示至少保留一种。
- 导出搜索结果文件包含系统信息头，且其中搜索不到最近一次语音输入的文字内容。

## 3.14 移动麦克风（多设备接入，F-MIC-01 ~ F-MIC-07）

> 移动客户端为**独立 Git 子项目**（建议仓库名 `vt-mobile`），与桌面端本仓库（`vt`）分别版本化、分别发布；本节定义两端协同的产品需求。

**用户故事**
- 作为使用台式机的程序员，我的电脑没有麦克风，我希望用手机扫码配对后按住手机说话，文字直接上屏到电脑。
- 作为笔记本用户，内置麦克风收音差、风扇噪声大，我希望用手机的麦克风获得更清晰的识别效果。
- 作为腱鞘炎用户，我希望离开工位倒水、踱步时也能继续口述需求，回到座位时文字已经在屏幕上。
- 作为 Vibe Coding 用户，我希望手机就像一个“带控制键的无线话筒”：按住话筒键说话，说完顺手点一下话筒上的“回车”就把需求发给 AI 编程助手，全程不碰电脑键盘。

### 3.14.1 功能概述

- 移动客户端（手机 / 平板，Android 与 iOS）将设备麦克风采集的音频实时传输到桌面端，由桌面端完成识别与上屏——**识别始终发生在桌面端，移动端不内置识别模型**，保证“本地优先”的隐私承诺不变。
- 已连接的移动设备在桌面端“通用 › 录音环境 › 选择麦克风”中呈现为一个可选麦克风（显示设备名，如“小周的 Pixel”），与其他麦克风统一调度。
- 移动端也可作为**遥控录音器**：在移动端按住说话，等同于在桌面端按下录音快捷键，结果上屏到桌面端当前光标处。
- **话筒与控制键一体**：移动客户端的录音界面是一个“带控制键的无线话筒”——录音按钮周围环绕一组控制键（回车、换行、退格等），说完即按，完成“口述 → 上屏 → 发送 / 换行 / 修正”的完整闭环，实现离开键盘的自由 Vibe Coding（见 3.14.5）。

### 3.14.2 配对与连接方式

| 方式 | 流程 | 适用场景 | 优先级 |
| --- | --- | --- | --- |
| **扫码配对（默认推荐）** | 桌面端“移动麦克风”页展示二维码（内容包含：一次性随机配对码、桌面端局域网地址、服务端口）；移动客户端扫码 → 双方校验随机码 → 建立配对 | 大多数场景，操作最简单 | P1 |
| **局域网设备发现** | 桌面端通过 mDNS 在局域网广播服务；移动客户端“附近的桌面端”列表中自动出现可配对设备，点击后桌面端弹确认框完成配对 | 不便扫码（如投屏演示） | P1 |
| **手动连接码** | 桌面端显示 6 位一次性连接码，移动端手动输入完成配对 | 扫码与 mDNS 均不可用时兜底 | P2 |
| **USB 有线连接** | 移动端通过数据线连接电脑，自动识别并提示配对 | 无网络 / 网络隔离环境、对延迟与稳定性要求极高的场景 | P2 |

**业务规则**
1. 配对码 / 连接码为一次性，有效期 2 分钟，过期自动刷新；配对成功后双方保存长期配对令牌，之后自动重连无需重新配对。
2. 配对成功后，桌面端与移动端**互发确认通知**（桌面端通知“XXX 的手机已连接”，移动端震动 + 提示）。
3. 配对仅在本机局域网或 USB 通道内完成，不经过任何云端服务器。
4. 一台桌面端可同时配对多台移动设备，但同时只允许一台处于“录音输入”状态（先按先得，其他设备提示“另一台设备正在录音”）；一台移动设备可保存多个桌面端（如家里电脑、公司电脑），在客户端首页切换。

### 3.14.3 桌面端“移动麦克风”设置页

- 入口：通用 › 录音环境 › “移动麦克风”卡片（“管理设备”按钮），以及托盘菜单“连接手机”。
- 页面内容：
  - 总开关“允许移动设备连接”（默认开）；
  - “添加设备”按钮：弹出配对面板（二维码 + 一次性随机码 + 6 位手动连接码，标签页切换；二维码内容随随机码每次刷新）；
  - 已配对设备列表：设备名、连接方式（局域网 / USB）、状态（已连接 / 离线）、信号与延迟、操作（重命名、解除配对）；
  - 安全设置：仅允许已配对设备（默认开）、新设备连接时桌面端须确认（默认开）、传输加密（默认开，不可关闭）。

### 3.14.4 移动客户端功能

- **录音主界面（带控制键的无线话筒）**：居中大按钮（按住说话 / 切换模式，跟随桌面端设置），显示当前连接的桌面端名称、连接状态、电量；录音中显示音量波形与时长。录音按钮下方 / 两侧为**控制键区**（见 3.14.5），与录音按钮共同构成一个“话筒面板”，单手握持即可拇指完成“说话 + 按键”。
- **模式跟随**：移动端可看到桌面端当前场景与激活的 AI 模板名称；长按录音按钮可临时选择本次使用的模板（列表与桌面端同步）。
- **状态反馈**：上屏成功 / 降级 / 失败时移动端震动 + 文字提示，与桌面端悬浮球状态一致。
- **设置页**：音质（省流量 / 标准 / 高音质，默认标准）、锁屏后保持连接（默认开）、自动重连（默认开）、断开时提醒（默认开）、控制键布局（进入 3.14.5 的布局编辑器）。
- **权限**：仅需麦克风权限与局域网通信权限；不索取通讯录、定位等无关权限（Android 局域网发现所需的近似位置权限须单独说明用途）。

### 3.14.5 话筒控制键（F-MIC-07）

**功能说明**
- 话筒面板上的控制键按下后，桌面端在**当前光标所在应用**中执行对应按键——与在电脑键盘上按下效果一致，从而支持“说完就发”的完整闭环。

**默认控制键布局**（录音按钮周围 6 键，均可定制）：

| 位置 | 默认键 | 说明 |
| --- | --- | --- |
| 主位（录音键右侧，最顺手） | 回车 / 发送 | 说完即按，把需求发给 AI 编程助手；终端场景下同样受终端安全保护约束（默认不执行，仅上屏） |
| 次位 | 换行 | Shift+回车，在对话框中换行而不发送 |
| 次位 | 退格 | 删除光标前一个字符；长按连续删除 |
| 次位 | 删除上一句 | 撤销本产品上一次语音上屏（同按键口令） |
| 次位 | Tab / 缩进 | 焦点切换或缩进 |
| 次位 | Esc | 取消录音 / 关闭弹窗 |

**可定制配置**
- 每个键位可更换为：
  - **单键**：回车、换行、退格、Tab、Esc、方向键（↑↓←→）、删除、空格、Home / End、PageUp / PageDown；
  - **组合键**：Ctrl/Command + 任意键（如 Ctrl+Z 撤销、Ctrl+S 保存、Ctrl+Enter 发送），桌面端按当前操作系统自动映射修饰键；
  - **本产品动作**：开始 / 结束录音、删除上一句、触发指定 AI 模板（如“结构化 Prompt”）、切换场景锁定；
  - **隐藏该键位**（精简布局）。
- **布局方案**：支持保存多套布局并按场景切换，内置三套：
  - **AI 对话**（默认）：回车、换行、退格、删除上一句、Tab、Esc；
  - **编码**：换行、Tab、退格、方向键、撤销（Ctrl+Z）、保存（Ctrl+S）；
  - **终端**：仅退格、Esc、Ctrl+C（中断），**不提供回车键**（与终端安全保护一致，防止远程误执行命令）。
- 布局可导出 / 导入（与桌面端备份文件互通），团队可共享布局。
- 控制键区支持左手 / 右手模式（键位镜像），适配单手握持。

**业务规则**
1. 控制键的生效目标是桌面端**当前焦点窗口**；与语音上屏的目标窗口规则一致（录音开始时锁定）。
2. 终端场景下：布局自动切换为“终端”方案（用户可改），回车类按键默认不存在；若用户手动添加回车键，桌面端执行前弹一次确认并遵循 3.2.5 的终端安全保护设置。
3. 控制键按下时移动端给轻震动反馈；桌面端悬浮球短暂显示键名（如“回车”），让用户知道远程按键已生效。
4. 连接断开期间按下的控制键**不缓存、不补发**，避免恢复连接后误执行。
5. 控制键不经过任何云端；与音频使用同一加密通道。

**验收标准**
- 手机话筒面板说“给这个接口加上重试机制”，松手上屏后按面板上的“回车”，AI 对话中的消息被发送，全程未碰电脑。
- 把主位键改为“Ctrl+Enter”后，按下在桌面端等效于 Ctrl+Enter。
- 切换到终端窗口时，面板自动变为“终端”布局，默认布局中找不到回车键。
- 断网期间按控制键，恢复连接后不会补发。

### 3.14.6 异常与边界

| 场景 | 行为 |
| --- | --- |
| 录音中连接断开 | 桌面端立即结束录音，已采集部分正常识别上屏；悬浮球提示“移动设备连接中断，已输入已录制部分”；移动端震动提醒并自动重连 |
| 移动端来电 / 被其他应用打断 | 同“连接断开”处理；通话结束后自动重连 |
| 移动端电量低于 15% | 移动端提示；桌面端设备列表显示低电量标记 |
| 桌面端休眠 / 锁屏 | 连接保持；桌面端休眠唤醒后自动恢复（锁屏期间是否允许录音由桌面端设置决定，默认允许） |
| 局域网隔离（公司网络禁止设备互访） | 引导用户使用 USB 有线连接或手机热点直连；常见问题提供排查指引 |
| 未配对设备尝试连接 | 桌面端弹出确认框，用户拒绝则忽略并记录；连续 3 次被拒绝的来源 10 分钟内不再提示 |
| 控制键在桌面端无焦点时按下 | 不执行任何动作，移动端提示“电脑上没有可操作的窗口” |

**验收标准**
- 桌面端展示二维码，移动客户端扫码后 5 秒内完成配对并互发通知；之后杀掉移动端应用重开，自动重连成功。
- 手机按住说话，桌面端光标处上屏；录音中拔掉手机网络，已录部分正常上屏且两端均有提示。
- 在桌面端“选择麦克风”中能看到已连接的手机设备，并可将其设为默认输入源。
- 未配对设备在同一局域网内无法向桌面端发送音频或按键指令。

## 3.15 系统托盘与首次使用引导（F-SYS-01、F-SYS-02）

### 3.15.1 托盘图标与菜单

- 图标状态：空闲（常规）、录音中（红点）、处理中（动效）、异常（黄色感叹号，如模型缺失 / 权限缺失）。
- 菜单项：打开语音输入小窗、打开设置、连接手机（打开“移动麦克风”配对面板）、当前场景（子菜单可“锁定场景”）、暂停语音输入（暂停期间快捷键不响应）、口令速查卡、检查更新、退出。

### 3.15.2 首次使用引导

- 流程见 2.3.3。每一步可“上一步 / 下一步”，除“麦克风权限”和“下载模型”外均可跳过。
- 权限缺失时给出图文指引并提供“打开系统设置”按钮；授权后自动检测并进入下一步。
- 引导末尾提供可选步骤“把手机变成麦克风”：展示移动客户端下载方式与配对二维码入口，可跳过。

**验收标准**
- 新用户按引导完成后，能在练习框中成功完成一次语音输入与一次命名风格口令。
