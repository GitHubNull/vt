# 第 1 章 产品概述

## 1.1 背景

### 1.1.1 行业背景

1. **AI 编程改变了程序员的输入结构。** 随着 AI 编程助手（IDE 内置对话、命令行编程智能体、浏览器中的大模型对话）普及，“Vibe Coding”成为常态：程序员越来越多的时间在**用自然语言描述需求、约束、修改意见**，而不是逐字敲代码。一次高质量的需求描述往往有数百字，键盘输入成为新的瓶颈。
2. **程序员的日常输入远不止代码。** Commit 信息、Code Review 评论、技术文档、Issue 回复、即时通讯沟通、会议纪要……这些都是“中英混杂、充满术语”的文本。
3. **本地语音识别模型已经成熟。** 开源离线语音识别模型在普通个人电脑上即可实时运行，让“隐私安全 + 低延迟”的本地语音输入成为可能。
4. **健康诉求。** 长期键盘输入带来的腱鞘炎、颈椎与肩部劳损是程序员的职业病，语音输入是重要的替代与补充手段。

### 1.1.2 用户痛点

| 编号 | 痛点 | 具体表现 |
| --- | --- | --- |
| PP-01 | 技术术语识别差 | 通用输入法把“Redis”识别成“瑞迪斯”，把“Kubernetes”识别成“酷伯内特斯”，把“useState”识别成“优斯 state” |
| PP-02 | 中英混说一塌糊涂 | 大小写错误（“github”而不是“GitHub”）、中英文之间空格混乱、英文被强行翻译成中文 |
| PP-03 | 命名风格无法表达 | 想输入 userName、user_name、USER_NAME 时，语音输入无从下手 |
| PP-04 | 符号无法口述 | 括号、箭头、等号、管道符等编程符号无法通过语音得到；中文输入环境下标点被转成全角 |
| PP-05 | 口语化、口误多 | “嗯、啊、那个”等语气词以及“不对，改成……”的自我修正直接上屏，需手动清理 |
| PP-06 | 隐私顾虑 | 口述内容常涉及公司代码、业务逻辑、内部系统名称，使用云端语音服务存在泄露风险 |
| PP-07 | 与开发工作流冲突 | 默认快捷键与 IDE 快捷键冲突（例如 F2 是多数 IDE 的“重命名”）；在终端中误触发回车可能直接执行命令 |
| PP-08 | 写给 AI 的需求不够结构化 | 口述的需求零散、缺少约束和验收标准，AI 编程助手理解偏差，反复返工 |

## 1.2 产品定位

### 1.2.1 一句话定位

**VibeType（码语）是一款面向程序员的、隐私优先的桌面 AI 语音输入法：在任何应用的光标处，把程序员“说的话”准确地变成“程序员想要的文字”——术语正确、命名规范、符号到位，并可一键交给 AI 整理成结构化的提示词、Commit 信息或技术文档。**

### 1.2.2 核心价值主张

| 价值 | 说明 | 对应痛点 |
| --- | --- | --- |
| 懂技术 | 内置技术栈词库、专有名词与替换词典，术语大小写与拼写准确 | PP-01、PP-02 |
| 懂代码 | 编程口令：命名风格转换、符号口述、按键口令 | PP-03、PP-04 |
| 懂场景 | 自动识别当前应用（IDE / 终端 / AI 对话 / 文档 / 即时通讯），切换对应输出规则；终端安全保护 | PP-02、PP-07 |
| 懂意图 | 可选 AI 后处理：口误纠错、结构化 Prompt、Commit 信息、代码注释、技术翻译 | PP-05、PP-08 |
| 守隐私 | 语音识别默认本地离线；是否使用云端 AI 由用户决定；外发前敏感信息检测 | PP-06 |
| 可编排 | 开放 MCP 服务，AI 编程智能体可以“向用户语音提问”、查询与建议专有名词 | PP-08 |

### 1.2.3 产品原则

1. **本地优先**：没有网络、没有任何 API Key 时，核心语音输入功能必须完整可用。
2. **零打扰**：常驻后台，一个快捷键完成“说—转—上屏”，不抢焦点、不弹多余窗口。
3. **结果可预期**：同样的话在同样的场景下得到同样的结果；任何自动改写都可以被关闭。
4. **安全第一**：宁可少做一步（例如不自动回车），也不替用户执行有风险的动作。
5. **开放可扩展**：词典、模板、场景规则、AI 供应商均可导入导出与自定义。

## 1.3 目标用户

### 1.3.1 用户分层

| 层级 | 用户群体 | 说明 |
| --- | --- | --- |
| 核心用户 | 重度使用 AI 编程助手的软件工程师 | 每天大量向 AI 描述需求，对输入效率最敏感 |
| 重要用户 | 前端 / 后端 / 全栈 / 运维 / 数据工程师 | 日常需要写 Commit、评审意见、文档、即时通讯消息 |
| 重要用户 | 技术负责人、架构师、开源维护者 | 文字输出量大：设计文档、评审、Issue 回复 |
| 关怀用户 | 有腱鞘炎、肩颈劳损或其他输入障碍的开发者 | 需要尽可能减少键盘输入 |
| 延伸用户 | 计算机专业学生、技术写作者 | 学习笔记、技术文章 |

### 1.3.2 用户画像

**画像 A：Vibe Coder —— 阿杰（后端工程师，5 年经验）**

- 工作方式：每天在 IDE 的 AI 对话面板和命令行编程智能体中工作 6 小时以上，一天要写几十段需求描述。
- 典型诉求：“我说‘给 OrderService 加一个基于 Redis 的分布式锁，超时三十秒，失败重试三次’，屏幕上就应该是这句话，而不是‘order 色维斯’和‘瑞迪斯’。”
- 担忧：公司代码与业务信息不能外传，不允许使用云端语音识别。
- 成功标准：向 AI 描述需求的时间减少一半以上。

**画像 B：前端工程师 —— 小雨（3 年经验）**

- 工作方式：VS Code + 浏览器，频繁在飞书 / Slack 中沟通。
- 典型诉求：说出“驼峰 handle submit click”得到 handleSubmitClick；说“烤串 main content wrapper”得到 main-content-wrapper。
- 担忧：中英文混排时空格和标点乱七八糟，发出去的消息不专业。

**画像 C：技术负责人 —— 老周（12 年经验）**

- 工作方式：大量 Code Review、设计评审与技术会议。
- 典型诉求：口述评审意见并自动整理成“问题—原因—建议”的结构。
- 担忧：评审意见语气生硬，需要 AI 帮忙润色得专业、礼貌、可执行。

**画像 D：腱鞘炎康复期的独立开发者 —— 阿 K**

- 工作方式：独立维护两个开源项目，需要用英文回复 Issue。
- 典型诉求：用中文说，输出地道的英文技术回复；尽量少碰键盘，连回车、换行都希望能用语音完成。

## 1.5 竞品分析

> 以下为基于公开信息与使用体验的**定性**比较，用于明确差异化方向，不构成对任何第三方产品的评价或背书。

| 维度 | 系统自带听写 | 主流中文输入法的语音输入 | 通用 AI 语音输入工具 | 专业语音编程工具 | 本产品 |
| --- | --- | --- | --- | --- | --- |
| 中文识别 | 一般 | 好 | 好 | 弱（多以英文为主） | 好 |
| 技术术语 / 中英混说 | 弱 | 一般 | 一般 | 好（英文） | **好（中英双语术语）** |
| 命名风格 / 符号口述 | 无 | 无 | 无 | 有，但学习成本高 | **有，口令简单易记** |
| 场景感知 | 无 | 弱 | 部分 | 有 | **有（IDE / 终端 / AI 对话 / 文档）** |
| AI 后处理 | 无 | 部分 | 有 | 少 | **有，模板可自定义、可绑定快捷键** |
| 隐私 | 视平台而定 | 多为云端 | 多为云端 | 多为本地 | **默认本地离线** |
| 开放性 | 无 | 无 | 少 | 脚本扩展 | **MCP 服务、导入导出、开源** |
| 学习成本 | 低 | 低 | 低 | 高 | **低（先能用，再进阶）** |

**参考原型（VocoType）分析：** 原型是一款隐私安全的 AI 语音输入法，已具备替换词典、专有名词、提示词模板、MCP 服务、多 AI 供应商、通用输出设置等较完整的能力框架。本产品沿用其“设置窗口 + 语音小窗 + 悬浮球”的产品形态与信息架构，并在以下方面针对程序员重新设计：

1. 新增一级模块“编程”：场景规则、编程口令、技术词库；
2. 内置模板全面替换为编程向（结构化 Prompt、Commit 信息、Code Review、技术翻译等）；
3. 默认快捷键避开 IDE 常用键；终端场景默认不自动回车；
4. 补齐原型中未展示的“我的”“统计”“常见问题”页面设计；
5. 修正原型中的界面瑕疵（侧边栏重复渲染、AI 供应商列表重复项等，详见第 4 章）。

## 1.7 范围边界

### 1.7.1 本期范围（In Scope）

- 桌面端：Windows、macOS、Linux；
- 全局语音输入：任意应用光标处上屏；
- 编程增强：场景规则、编程口令、技术词库、专有名词、替换词典；
- AI 后处理：提示词模板、AI 供应商管理、MCP 服务；
- 设置、统计、常见问题、关于、首次使用引导。

### 1.7.2 非本期范围（Out of Scope）

| 不做的事 | 原因 |
| --- | --- |
| 移动端（iOS / Android） | 程序员核心工作场景在桌面端 |
| 全语音操控 IDE（导航、选择、重构等） | 学习成本高、场景窄，非本期定位；后续可通过 IDE 集成探索 |
| 代码补全 / 代码生成引擎 | 这是 AI 编程助手的职责，本产品专注“输入”，与之互补而非竞争 |
| 账号体系与云同步 | 与本地优先原则冲突，本期以本地备份 / 恢复替代 |
| 云端语音识别服务 | 本期坚持本地识别；未来是否作为可选项另行评审 |
| **音视频文件转录**（含会议录音转文字、字幕导出、AI 纪要） | **已决策移除（2026-10-09，PRD v1.1）：目前及未来较长一段时间内均不提供。产品聚焦“实时语音输入”唯一核心场景，避免能力泛化稀释定位；参考原型中的“音视频转录”导航项不实现。如未来重新评估须重新立项评审** |
| 实时会议同传、字幕直播 | 非核心场景，且依赖已移除的音视频转录能力 |
