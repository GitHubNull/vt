## 五、文档约定

- **优先级**：
  - **P0**：必须有，缺失则产品不可用或核心价值不成立；
  - **P1**：应该有，显著提升体验或差异化，正式版必须交付；
  - **P2**：可以有，视资源排期，可在后续版本交付。
- **需求措辞**：“必须”表示强制要求；“应当”表示强烈建议，如不满足需在评审中说明理由；“可以”表示可选。
- **功能编号**：形如 `F-INPUT-01`，用于需求、设计、测试之间的追溯。
- **示例说明**：文档中出现的英文标识符（如 userName）仅为“用户说出什么、屏幕上应当出现什么”的产品示例，不代表任何实现方式。
