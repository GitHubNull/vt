## 1. 目标与范围

### 1.1 目标

实现桌面端 WebSocket 服务：移动设备的音频流、控制键、状态同步的统一加密通道。

### 1.2 范围内

- WsServer（`tokio-tungstenite`）：局域网接口监听，端口可配（写入 mDNS TXT 与二维码载荷）；
- 认证：首条消息必须为认证帧（长期令牌 / 一次性配对码），失败关闭并记录；
- 通道加密：默认开不可关；密钥协商在认证帧完成（具体方案实施时定稿并更新 tech/07）；
- 消息协议实现：tech/07 7.3.2 全部控制帧 + 二进制音频帧；
- 心跳：5 s 间隔，15 s 无心跳判定断连；
- 连接状态事件：`device:changed` 推送前端；
- 断连语义：录音中断连 → 立即结束录音、已采集部分照常识别上屏、双端提示（PRD 异常处理）。

### 1.3 范围外

- 音频源接入 AudioService（T-1014）；
- 控制键路由（T-1016）；
- Android 端实现（vt-mobile）。

- 复用：T-1011 令牌校验、T-001 事件广播。

## 4. 任务步骤

1. WsServer：监听、连接生命周期管理；
2. 认证帧处理（令牌 / 配对码两路径）；
3. 通道加密（协商与加解密，方案定稿后更新 tech/07 7.3.1）；
4. 协议帧编解码（serde JSON 控制帧 + 二进制音频帧）；
5. 心跳与断连判定；
6. 断连语义：录音中处理（与 AudioService 联动接口预留，T-1014 完成闭环）；
7. 单元测试：帧编解码、认证、心跳超时；
8. 联调：WebSocket 客户端脚本模拟设备连接 / 认证 / 心跳 / 断连。

## 5. 验收标准

- [ ] 未认证连接首帧非认证帧即关闭并记录；
- [ ] 持有效令牌连接成功，`device:changed` 事件推送；
- [ ] 通道加密生效（抓包验证无明文协议内容）；
- [ ] 心跳超时 15 s 判定断连，状态事件正确；
- [ ] 录音中断连：已采集音频照常识别上屏，双端收到提示；
- [ ] 服务仅监听局域网接口；
- [ ] tech/07 7.3.2 全部消息类型编解码正确。
