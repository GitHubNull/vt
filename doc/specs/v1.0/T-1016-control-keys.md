## 1. 目标与范围

### 1.1 目标

实现话筒控制键的桌面端路由：接收移动端控制键事件，按当前布局解析为按键 / 组合键 / 产品动作，注入桌面端焦点窗口。

> 移动端边界：控制键面板 UI 与布局编辑器在 vt-mobile（Android）；本任务实现桌面端的布局存储、同步、事件路由与执行。

### 1.2 范围内

- 布局数据模型：三套内置布局（AI 对话 / 编码 / 终端）+ 自定义布局；键位定义（单键 / 组合键 / 产品动作 / 隐藏）；左手 / 右手镜像标记；
- 布局存储与同步：存桌面端配置，连接时同步给移动端；布局导入导出（zip，与备份文件互通，NFR-S-07 校验）；
- ControlKeyRouter：`control_key` 帧 → 当前布局解析 → InjectService 按键注入 / 产品动作（开始 / 结束录音、删除上一句、触发 AI 模板、切换场景锁定）；
- 场景联动：终端场景自动切换终端布局（**不提供回车键**）；用户手动加回车键时桌面端执行前弹一次确认（与 T-515 终端安全一致）；
- 生效目标：录音开始时锁定的焦点窗口；无焦点时不执行并回 `result_notify` 提示"电脑上没有可操作的窗口"；
- 断连语义：断连期间控制键不缓存、不补发（NFR-S-09）。

### 1.3 范围外

- 移动端控制键面板与布局编辑器 UI（vt-mobile）；
- 按键注入平台能力（v0.5 T-511 已建）。

## 2. 需求依据

- F-MIC-07：话筒控制键（PRD 3.14.5 节全部业务规则）；
- NFR-S-09：同一加密通道；断连不缓存不补发；终端默认无回车键；
- [tech/07](../../tech/07-mobile-link.md) 7.4。

## 3. 技术上下文

- 修改：DeviceHub（ControlKeyRouter）；
- 新建：布局模型与存储（配置目录 `layouts/`）、布局管理命令；
- 复用：T-1013 通道、T-511/T-514 按键注入、T-515 终端约束、T-501 场景。

## 4. 任务步骤

1. 布局数据模型与三套内置布局（PRD 3.14.5 键位清单）；
2. 布局同步：连接 / 布局变更时推送移动端；
3. ControlKeyRouter：事件 → 布局解析 → 执行（按键 / 动作）；
4. 终端场景约束：自动切终端布局、回车键确认流程；
5. 焦点锁定：录音开始时锁定目标窗口，控制键注入该窗口；无焦点回提示；
6. 布局导入导出（zip + 校验）；
7. 单元测试：布局解析、终端约束、断连丢弃；
8. 联调：模拟客户端发控制键帧验证执行。
