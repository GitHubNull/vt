# T-1014 移动音频源接入

| 项目 | 内容 |

| 所属阶段 | v1.0 正式版 |

## 1. 目标与范围

### 1.1 目标

把已连接的移动设备接入 AudioService 作为可选音频源：移动端录音音频流经通道进入桌面端识别链路，与物理麦克风统一调度。

### 1.2 范围内

- 移动音频源适配：WebSocket 音频帧 → AudioService 帧流（重采样到 16 kHz 单声道，如需要）；
- 设备作为麦克风出现在"选择麦克风"列表（显示设备名）；
- 移动端 `start_record` / `stop_record` / `cancel_record` 控制帧驱动录音状态机（等同快捷键）；
- 互斥规则：同一时刻一台设备处于录音输入状态（先按先得）；移动端触发与本地触发互斥；
- 状态同步：`state_sync`（场景、激活模板、录音状态）与 `result_notify`（上屏结果）推送移动端；
- 延迟监测：音频往返延迟统计（目标 ≤200 ms，PRD 兼容性指标），设备列表显示。

### 1.3 范围外

- 控制键路由（T-1016）；
- 虚拟麦克风设备（F-MIC-05，v1.x）；
- Android 端实现（vt-mobile）。

## 2. 需求依据

- F-MIC-04：移动客户端录音（PRD 3.14 节：识别在桌面端、统一调度、先按先得）；
- PRD 兼容性：局域网良好环境音频往返延迟 ≤200 ms；断连已采集音频不丢失；
- [tech/07](../../tech/07-mobile-link.md) 7.1 / 7.3；
- [tech/05](../../tech/05-core-pipeline.md) 5.2 状态机。

## 3. 技术上下文

- 修改：AudioService（多音频源抽象：物理 / 移动设备）、DeviceHub（音频帧路由）；
- 复用：T-1013 通道、T-005 AudioService、T-012 链路。

## 4. 任务步骤

1. AudioService 音频源抽象（`AudioSource` trait：物理设备 / 移动设备）；
2. 移动音频帧接入与重采样；
3. 麦克风选择列表纳入移动设备（在线时）；
4. 移动端控制帧 → 录音状态机（含与本地触发的互斥）；
5. `state_sync` / `result_notify` 推送；
6. 延迟统计（时间戳 / 心跳测量）与上报；
7. 单元测试：源切换、互斥、重采样；
8. 联调：模拟客户端推音频帧完成端到端识别上屏。

## 5. 验收标准

- [ ] 已连接移动设备出现在麦克风选择列表（显示设备名）；
- [ ] 移动端开始 / 停止 / 取消录音驱动桌面端状态机正确；
- [ ] 移动音频识别上屏结果正确（端到端联调）；
- [ ] 一台设备录音中，另一台设备 / 本地触发被拒绝并提示（先按先得）；
- [ ] 移动端收到状态同步与结果通知；
- [ ] 局域网良好环境音频往返延迟 ≤200 ms（实测记录）；
- [ ] 断连时已采集音频不丢失（照常识别上屏）。

## 6. 测试要求

- `cargo test`：源抽象、互斥；
- 手动验证：模拟客户端端到端、延迟实测。
