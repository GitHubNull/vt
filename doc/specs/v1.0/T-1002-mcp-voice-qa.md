## 1. 目标与范围

### 1.1 目标

实现 MCP 语音提问能力：AI 智能体通过 MCP 向用户发起语音提问，用户语音回答，识别文本回传智能体。

### 1.2 范围内

- MCP tool 注册：`ask_user`（提问文本 + 可选选项）；
- 提问卡片 UI：不抢焦点的卡片展示提问，用户点击后语音回答（复用核心链路，跳过 AI Stage）；
- 回答回传：识别文本（经词典 Stage，是否经口令 / 混排由设置控制）作为 MCP 响应；
- 超时：用户未回答超时（可配，默认 120 s）返回超时错误；
- 用户忽略：卡片可关闭（视为拒绝，返回相应错误）；
- 并发：同时只处理一个提问，后续提问排队或拒绝（按 PRD 3.6 节）。

### 1.3 范围外

- 专有名词查询 / 建议能力（T-1003 的访问控制内注册，词库查询复用 DictService）；
- 移动端回答（v1.x 评估）。

## 2. 需求依据

- F-AI-10：MCP 语音提问（PRD 3.6 节用户故事与验收标准）；
- 产品原则 2：提问卡片不抢焦点；
- [tech/06](../../tech/06-ai-and-mcp.md) 6.2.3 链路图。

## 3. 技术上下文

- 修改：McpServer（注册 ask_user）、前端提问卡片组件；
- 复用：核心链路（T-012）、DictService、T-008 不抢焦点窗口机制。

## 4. 任务步骤

1. `ask_user` tool 实现：参数校验 → 提问入队 → 等待回答 → 返回文本 / 超时 / 拒绝；
2. 提问卡片窗口（不抢焦点）：提问文本、录音按钮、关闭；
3. 回答链路：录音 → 识别 → 词典 Stage → 回传；
4. 超时与拒绝的 MCP 错误响应；
5. 并发语义实现（PRD 规则）；
6. 联调：MCP Inspector / 真实智能体发起提问全流程。
