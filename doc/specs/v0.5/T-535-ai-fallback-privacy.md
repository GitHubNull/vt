| 前置依赖 | T-534 |

## 1. 目标与范围

### 1.1 目标

实现 AI 处理的可靠性兜底与隐私闸门：超时 / 失败降级为原文上屏；首次外发前用户确认；发送前敏感信息检测与打码（基础版）。

### 1.2 范围内

- 超时降级（F-AI-05）：单次 AI 调用超时（默认 15 s 可配）/ 失败 → 原始识别文本直接上屏 + 降级提示（悬浮球 / 小窗）；
- 断网降级（NFR-R-04）：云端供应商不可达自动标记，本地输入链路不受影响；
- 首次外发确认（NFR-PR-03）：首次向某供应商发送文本前弹窗告知（发送内容类型、供应商），用户确认后持久化该供应商的确认记录；
- 敏感信息检测基础版（NFR-S-03）：外发前扫描密钥 / 私钥 / 密码赋值等模式，命中自动打码并提示（完整规则库在 v1.0 T-1021）。

### 1.3 范围外

- 敏感信息检测完整规则库（v1.0 T-1021）；
- 隐私与安全设置分组（v1.0 T-1022）。

## 2. 需求依据

- F-AI-05：超时降级（PRD 3.5 节）；
- NFR-PR-03：首次外发前弹窗告知并获确认；任何情况下不发原始音频；
- NFR-S-03：敏感信息检测本地完成；
- NFR-R-04：断网时云端 AI 降级、本地输入不受影响；
- [tech/06](../../tech/06-ai-and-mcp.md) 6.1.4 / 6.1.5。

## 3. 技术上下文

- 修改：AiPipeline（超时 / 降级 / 闸门）、前端确认弹窗组件；
- 复用：T-534 AI Stage、T-003 配置（确认记录持久化）。

## 4. 任务步骤

1. AI 调用包装：超时控制 + 错误分类（超时 / 网络 / 供应商错误）→ 降级路径；
2. 降级提示：`recording:result { Degraded, reason }` 事件与 UI 反馈；
3. 首次外发确认弹窗：供应商维度确认记录持久化，撤销确认（设置中）入口预留；
4. 敏感信息检测器：基础规则集（密钥 / 私钥 / 密码赋值），命中打码 + 提示；
5. 断网检测：供应商不可达标记与恢复；
6. 单元测试：超时降级、确认记录、打码规则；
7. 手动验证：拔网线 / 超时（慢响应模拟）/ 含密钥文本外发三场景。

## 5. 验收标准

- [ ] AI 调用超时（>15 s）自动降级为原文上屏并提示降级原因；
- [ ] 断网时云端模板调用降级，纯本地语音输入不受影响；
- [ ] 首次向某供应商外发前弹窗，确认后不再弹（该供应商）；拒绝则不发送并降级；
- [ ] 含 API Key 样式文本外发前被打码并提示（测试样本验证）；
- [ ] 任何路径不向云端发送音频（代码评审确认）；
- [ ] 降级与确认记录不泄露用户文本到日志。

## 6. 测试要求

- `cargo test`：降级、打码、确认记录；
- 手动验证：三场景（超时 / 断网 / 敏感内容）。
