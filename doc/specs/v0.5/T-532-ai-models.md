## 1. 目标与范围

### 1.1 目标

实现供应商维度的大模型列表管理：从供应商拉取可用模型、手动维护模型列表、连通性测试。

### 1.2 范围内

- 拉取模型：`list_models` 命令（供应商支持时），结果合并进供应商配置；
- 手动模型管理：添加 / 删除模型条目（供应商不支持列表 API 时的兜底）；
- 连通性测试：`test_connection` 命令，返回延迟与错误详情（错误编号）；
- 当前默认模型选择（按供应商）。

### 1.3 范围外

- 设置页 UI（T-536）；
- 模板调用时的模型路由（T-534）。

## 2. 需求依据

- F-AI-07 / F-AI-08：PRD 3.7 节业务规则与验收标准；
- [tech/06](../../tech/06-ai-and-mcp.md) 6.1.3。

## 3. 技术上下文

- 修改：`ai_pipeline.rs` 与 `commands/ai.rs`；
- 复用：T-531 适配器与凭据层。

## 4. 任务步骤

1. `list_models` 命令：调适配器、结果规范化（id / 名称）、合并持久化；
2. 手动模型条目 CRUD；
3. `test_connection`：最小请求探测，返回延迟 ms 与错误编号；
4. 默认模型选择持久化；
5. 单元测试：结果合并、错误映射；
6. 联调：Ollama 拉取模型列表、云端供应商连通性测试。

## 5. 验收标准

- [ ] 支持列表 API 的供应商可一键拉取模型列表；
- [ ] 不支持的供应商可手动添加 / 删除模型；
- [ ] 连通性测试返回延迟或带错误编号的失败原因；
- [ ] 默认模型选择持久化并被后续调用使用；
- [ ] 错误响应不含 API Key（NFR-S-02）。

## 6. 测试要求

- `cargo test`：合并逻辑、错误映射；
- 手动验证：Ollama 与至少一个云端供应商。
