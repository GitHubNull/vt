> **v1.x SPEC 说明**：方向性规格，立项执行前先细化 PRD 再修订本 SPEC。本任务强依赖 ASR 引擎的流式（streaming）识别能力，立项时先验证引擎支持度。

## 1. 目标与范围

### 1.1 目标

录音过程中实时显示识别中间结果（边说边出字），录音结束时以最终结果上屏。

### 1.2 范围内

- ASR 流式推理：引擎流式接口接入（部分结果 / 稳定结果两级）；
- 预览 UI：悬浮球 / 小窗内实时文本预览（中间结果与稳定结果的视觉区分）；
- 管线协同：中间结果只预览不过后处理管线；最终结果走完整管线（词典 / 口令 / 混排）后上屏；
- 性能约束：流式推理的 CPU / 内存增量评估（NFR-P-06/07 仍须达标）；
- 设置项：实时预览开关（默认状态立项时 PRD 定）。

### 1.3 范围外

- 边说边上屏（直接写入目标应用的流式上屏，风险高，另行评估）；
- 移动端链路改动（协议如需扩展另行评审）。

## 2. 需求依据

- PRD 6.1 v1.x：实时"边说边出字"预览；
- [tech/05](../../tech/05-core-pipeline.md) 5.3.3（v0.1 为整段模式，流式另行设计——本章即该设计的落地任务）；
- NFR-P-03/04：流式不得恶化最终上屏延迟。

## 3. 技术上下文

- 修改：AsrService（流式推理路径）、悬浮球 / 小窗（预览 UI）；
- 引擎流式能力验证是立项前置条件。

## 4. 任务步骤（方向性）

1. 立项细化 PRD（预览交互、默认开关、验收标准）；
2. ASR 引擎流式能力验证（spike）；
3. 流式推理接入与中间结果事件；
4. 预览 UI 与最终结果衔接；
5. 性能回归（NFR-P 全量复测）。

## 5. 验收标准（方向性，立项时细化）

- [ ] 录音中实时显示识别中间结果，与语音内容基本同步；
- [ ] 中间结果与最终结果视觉区分明确；
- [ ] 最终结果仍走完整后处理管线，上屏内容与非流式模式一致；
- [ ] NFR-P-03/04/06/07 指标无回归（实测对比）；
- [ ] 预览可开关，关闭后行为与 v1.0 一致。

## 6. 测试要求

- `cargo test`：流式事件与结果衔接；
- 性能基准复测；
- 三平台手动验证。

## 7. 完成定义（DoD）

- PRD 细化后的验收标准全部通过；
- tech/05 更新流式设计；
- 提交信息：`feat: 实时边说边出字预览`。
