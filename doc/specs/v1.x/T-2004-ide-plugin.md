> **v1.x SPEC 说明**：方向性规格，立项执行前先细化 PRD 再修订本 SPEC。IDE 插件可能涉及独立子项目（如 vt-vscode），仓库归属立项时确定。

## 1. 目标与范围

### 1.1 目标

通过 IDE 插件获得比窗口识别更精确的场景上下文（当前文件语言、项目、光标上下文），增强场景感知与口令准确性。

### 1.2 范围内（候选方向，立项时取舍）

- IDE 插件（候选：VS Code 先行）：上报当前文件语言 / 项目名 / 光标位置等上下文；
- 桌面端接收通道：复用 MCP 服务或本机 IPC（立项时定）；
- 上下文消费：场景规则细化（按文件语言调整口令 / 词库）、项目术语导入（F-CODE-07 联动）；
- 插件分发：IDE 市场发布流程。

### 1.3 范围外

- 非 IDE 类应用的插件；
- IDE 内语音 UI（插件只做上下文上报，UI 仍在桌面端）。

## 2. 需求依据

- PRD 6.1 v1.x：IDE 插件深度集成；
- F-CODE-01 场景规则的精度提升动机；
- F-CODE-07 项目术语导入（v1.0 已有基础）。

## 3. 技术上下文

- 复用：T-501 场景识别、T-1001 MCP 服务（或新 IPC 通道）；
- 插件技术栈（TypeScript / VS Code API）立项时确认仓库归属。

## 4. 任务步骤（方向性）

1. 立项细化 PRD（集成范围、上下文字段、验收标准）；
2. 通道方案评审（MCP 复用 vs 专用 IPC）；
3. VS Code 插件实现与上报；
4. 桌面端上下文消费（场景 / 词库联动）；
5. 插件市场发布。

## 5. 验收标准（方向性，立项时细化）

- [ ] IDE 插件可上报当前文件语言 / 项目上下文；
- [ ] 桌面端场景规则可消费 IDE 上下文（如按文件语言切换词库）；
- [ ] 插件断开时桌面端回退窗口识别，无故障；
- [ ] 上下文信息不写入日志（隐私）。

## 6. 测试要求

- 插件单测 + 桌面端联调手动验证。

## 7. 完成定义（DoD）

- PRD 细化后的验收标准全部通过；
- 提交信息：`feat: IDE 插件深度集成`。
