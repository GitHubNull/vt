## 1. 目标与范围

### 1.1 目标

把移动设备音频呈现为系统级虚拟麦克风设备，让任意应用（不限于 VT 自身链路）都能使用移动设备作为麦克风输入。

### 1.2 范围内

- 三平台虚拟音频设备方案（差异大，需分别设计）：
  - Windows：虚拟音频驱动（候选：VB-Cable 类第三方驱动集成 / 自研驱动，需评估签名与分发）；
  - macOS：CoreAudio 虚拟设备插件（HAL plugin）；
  - Linux：PipeWire / PulseAudio 虚拟源；
- 虚拟设备与 DeviceHub 音频流的桥接；
- 设置页：虚拟麦克风启用 / 停用、设备名；
- 安装包形态评估：驱动 / 插件的分发与安装引导。

### 1.3 范围外

- 移动端任何改动（vt-mobile）；
- 虚拟摄像头等音频以外能力。

## 2. 需求依据

- F-MIC-05：虚拟麦克风设备（PRD 功能清单，P2，v1.x）；
- [tech/07](../../tech/07-mobile-link.md) 7.6（平台差异说明）。

## 3. 技术上下文

- 复用：T-1013 通道、T-1014 音频流；
- 各平台虚拟设备技术选型在立项细化时确认并更新 tech/02 与 tech/07。

## 4. 任务步骤（方向性）

1. 立项细化：PRD 补充 F-MIC-05 业务规则与验收标准；各平台技术选型评审；
2. 平台方案原型验证（每平台先做 spike）；
3. 虚拟设备实现与音频桥接；
4. 设置页与安装引导；
5. 三平台验证。

## 5. 验收标准（方向性，立项时细化）

- [ ] 移动设备音频在系统录音设备列表中可见、可被第三方应用选用；
- [ ] 第三方应用（如系统录音机）通过虚拟麦克风录到移动端音频；
- [ ] 虚拟设备启用 / 停用可用，停用后设备消失；
- [ ] 延迟与音质指标（立项时在 PRD 中定义）达标；
- [ ] 三平台（或立项时确定的平台子集）验证通过。

## 6. 测试要求

- 各平台手动验证为主；
- 音频链路延迟实测。

## 7. 完成定义（DoD）

- PRD 细化后的验收标准全部通过；
- tech/07 7.6 更新为最终设计；
