## 二、SPEC 模板

每个 SPEC 文件遵循以下结构（章节齐全，无内容时写"无"）：

```markdown
# T-xxx 任务名称

| 项目 | 内容 |
| --- | --- |
| 任务编号 | T-xxx |
| 所属阶段 | v0.1 / v0.5 / v1.0 |
| 优先级 | P0 / P1 / P2（继承 PRD） |
| 覆盖需求 | F-XXX-01、NFR-X-01（PRD 编号） |
| 前置依赖 | T-yyy（无则写"无"） |

## 1. 目标与范围
### 1.1 目标
### 1.2 范围内（本任务做什么）
### 1.3 范围外（本任务明确不做什么）

## 2. 需求依据
（PRD 章节与功能编号、NFR 编号、技术文档章节的引用与摘要）

## 3. 技术上下文
（涉及的目录 / 文件、复用的已有模块、相关 tech/ 章节）

## 4. 任务步骤
（可执行粒度的步骤列表，每步有明确产出）

## 5. 验收标准
（可测试、可勾选的清单；映射 PRD 验收标准与 NFR 指标）

## 6. 测试要求
（单元测试 / 集成测试 / 手动验证步骤，含三平台要求）

## 7. 完成定义（DoD）
（代码 + 测试 + 文档 + 原则核查的收口清单）
```

## 三、编写与执行约定

### 给 SPEC 编写者

- SPEC 引用 PRD 功能编号时必须与 [PRD 第 2 章功能清单](../prd/02-信息架构与功能清单.md) 一致；
- 验收标准必须**可客观验证**（"运行 X 命令输出 Y"、"在 Z 应用中上屏结果为 W"），禁止"体验良好"类主观表述；
- 不估算所需时间；
- 涉及平台能力的任务，验收标准必须含三平台（Windows / macOS / Linux X11）手动验证项；
- 涉及数据的任务，验收标准必须含 [隐私检查清单](../tech/08-data-and-security.md) 8.9 的对照结果。

### 给执行者（AI 编程代理）

1. 执行前通读：SPEC 全文 → SPEC 引用的 PRD 章节 → SPEC 引用的 tech/ 章节；
2. 严格按"范围内"执行，"范围外"的内容不要做；
3. 验收标准逐条自证；无法验证的条目停下来报告，不得跳过；
4. 发现 SPEC 与 PRD / tech 文档冲突：停下来报告，不得自行取舍；
5. 遵守 AGENTS.md 3.2 产品原则与 3.6 Git 约定（提交信息中文 `类型: 简述`）；
6. 完成后更新对应子路线图中的任务状态（⬜ → ✅）。
