## 1. 目标与范围

### 1.1 目标

接入本地离线语音识别引擎，消费 AudioService 的录音结果并输出文本；实现模型文件的加载、校验与切换机制。

### 1.2 范围内

- ASR 引擎选型落地：在 Rust 生态中选择本地中文语音识别方案（候选：sherpa-rs / 其他支持中文的本地引擎），**选型结论与理由记录在本 SPEC 实施时更新到 tech/02**；
- AsrService：模型加载（`spawn_blocking`）、推理（`spawn_blocking`）、结果回调；
- 模型管理服务端：模型清单（内置推荐模型元数据）、下载（断点续传可选）、完整性校验（哈希）、切换、删除；
- 消费 `recording:audio_ready`：推理 → `recording:result { Ok, text }` 事件；
- 推理失败路径：错误编号 + 引导重新下载模型；
- 模型存数据目录 `models/`，不打进安装包（NFR-P-09）。

### 1.3 范围外

- 模型管理设置页 UI（T-014）；
- 后处理（词典 / 口令 / AI，T-011 及以后）；
- 流式"边说边出字"（v1.x）；
- 首次使用引导中的模型下载引导（v0.5 T-542）。

## 2. 需求依据

- F-INPUT-03：本地离线识别，断网可用（产品原则 1）；
- NFR-A-01：普通话通用文本字准确率 ≥95%（模型选型需满足）；
- NFR-P-03/04：推理耗时预算（[tech/05](../../tech/05-core-pipeline.md) 5.4）；
- NFR-P-06：含推荐模型空闲内存 ≤800 MB；
- [tech/04](../../tech/04-backend.md) 4.4 AsrService。

## 3. 技术上下文

- 新建：`src-tauri/src/services/asr.rs`、`src-tauri/src/commands/asr.rs`；
- 复用：T-005 的 `recording:audio_ready`；T-001 事件广播；T-003 配置（当前模型）；
- 模型下载用 `reqwest`（tech/02 已登记）。

## 4. 任务步骤

1. 调研并确定 ASR 引擎与推荐模型（中文普通话字准确率 ≥95% 为门槛），结论写入本任务 PR 描述并更新 tech/02；
2. 定义模型元数据（id、名称、档位、大小、哈希、下载地址）与 `models/` 目录布局；
3. 实现模型下载（进度事件）、哈希校验、加载、切换、删除；
4. 实现推理管线：音频帧 → 引擎输入格式转换 → `spawn_blocking` 推理 → 文本；
5. 接入 `recording:audio_ready`：推理完成广播 `recording:result { Ok, text }`；失败广播 `Failed` + 错误编号；
6. 性能埋点：推理耗时日志（对照 NFR-P-03/04 预算）；
7. 单元测试：元数据解析、哈希校验失败拒绝加载；集成测试：固定测试音频 → 识别结果包含预期关键词。

## 5. 验收标准

- [ ] 断网状态下：录音 → 识别 → 输出文本完整可用（产品原则 1）；
- [ ] 内置推荐模型在基准测试集（≥50 句普通话通用文本）字准确率 ≥95%（NFR-A-01）；
- [ ] ≤10 秒语音推理耗时 P95 ≤600 ms（基准机实测日志，为 NFR-P-03 总预算留余量）；
- [ ] 模型文件哈希损坏时拒绝加载并提示重新下载；
- [ ] 模型下载 / 删除 / 切换命令可用，下载进度事件正常；
- [ ] 安装包中不包含模型文件；
- [ ] 识别文本不写入日志（NFR-S-02）。

## 6. 测试要求

- `cargo test`：元数据 / 校验 / 格式转换；
- 集成测试：固定音频样本识别；
- 手动验证：断网识别、模型切换后识别生效。
