## 1. 目标与范围

### 1.1 目标

把已完成的各模块串联为完整价值链路：快捷键 / 小窗触发 → 录音 → 识别 → 替换词典 → 光标上屏，并完成性能与稳定性收口。

### 1.2 范围内

- 链路编排：录音会话结束 → AsrService → PostProcess → InjectService 的自动流转（此前各模块经事件 / 命令松散连接，本任务固化为正式管线）；
- 会话代次（generation）贯穿全链：取消 / 新会话使旧会话结果失效；
- 结果反馈闭环：上屏成功 / 降级（剪贴板路径）/ 失败 → `recording:result` → 悬浮球与小窗反馈；
- 性能收口：NFR-P-01/02/03 埋点核对与基准测试脚本（`src-tauri/benches/`）；
- 稳定性：连续 100 次录音循环无泄漏、无状态错乱（自动化脚本）。

### 1.3 范围外

- 新功能开发；
- 目标应用兼容性全矩阵测试（发布前手动执行，本任务覆盖五大类各一个代表应用）。

## 2. 需求依据

## 3. 技术上下文

- 修改：AudioService / AsrService / PostProcess / InjectService 之间的接线（AppState 组装处）；
- 新建：`src-tauri/benches/pipeline_bench.rs`（或脚本）、链路集成测试。

## 4. 任务步骤

1. 在 AppState 组装链路：`audio_ready` → AsrService → PostProcess → InjectService，各跳携带会话代次；
2. 结果事件统一：`recording:result { Ok | Degraded(reason) | Failed(code) }`，前端悬浮球 / 小窗消费；
3. 竞态收口：录音中再触发开始忽略；Processing 中触发开始忽略；取消使在途结果失效；
4. 埋点核对：快捷键事件→首帧、录音结束→上屏完成，日志输出耗时分解；
5. 基准测试脚本：固定音频样本驱动链路，输出 P50 / P95；
6. 稳定性脚本：模拟 100 次录音循环，断言内存增长与状态正确；
7. 五大类代表应用手动验证：VS Code（IDE）、终端、浏览器 AI 对话页、记事本（文档）、IM 输入框（沟通）。

## 5. 验收标准

- [ ] 快捷键与小窗两种入口全链路可用：说话 → 文字出现在光标处；
- [ ] 词典替换在链路中生效，Stage 关闭时原文上屏；
- [ ] 取消在任何阶段生效，无残留上屏；
- [ ] NFR-P-03 实测达标：≤10 秒语音 P95 上屏 ≤800 ms（基准机）；
- [ ] NFR-P-01/02 实测达标（预热 ≤150 ms / 非预热 ≤500 ms）；
- [ ] 100 次连续录音循环：无崩溃、内存增长 ≤20 MB、状态机始终回到 Idle；
- [ ] 五大类代表应用上屏正确；
- [ ] 断网状态下全链路可用（产品原则 1）。

## 6. 测试要求

- 基准测试脚本输出报告；
- 三平台手动验证全链路。
