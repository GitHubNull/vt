## 1. 目标与范围

### 1.1 目标

实现把文本输入到当前光标处的平台能力，含三级降级链：模拟键入 → 剪贴板粘贴 → 无焦点兜底（复制 + 通知）。

### 1.2 范围内

- `platform/inject/` 适配层：模拟键入（enigo / 平台 API）、剪贴板写入与恢复、模拟粘贴快捷键；
- InjectService：三级降级链编排、目标应用兼容性配置（已知异常应用走剪贴板路径的清单机制）；
- 无焦点检测与兜底：文本复制到剪贴板 + 系统通知"已复制，可手动粘贴"（F-INPUT-09）；
- 终端安全的基础约束：**本服务不输出任何回车 / 执行类按键**（NFR-S-05 的 v0.1 落地）；
- Tauri Command：`inject_text`（供联调与后续任务使用）。

### 1.3 范围外

- 场景识别（v0.5 T-501）与终端场景强化规则（v0.5 T-515）；
- 控制键注入（v1.0 T-1016）；
- 上屏后撤回能力（v0.5 管线化时评估）。

## 2. 需求依据

- F-INPUT-04：识别结果输入到光标处；
- F-INPUT-09：无焦点时复制到剪贴板并通知；
- NFR-S-05：终端场景默认禁止自动回车（v0.1 先落地"服务不输出回车"的硬约束）；
- [tech/05](../../tech/05-core-pipeline.md) 5.3.5 上屏三级路径；
- [tech/09](../../tech/09-cross-platform.md) 9.2.2 平台差异与权限降级。

## 3. 技术上下文

- 复用：T-001 AppError / 事件；T-003 配置（目标应用兼容性清单）；
- `enigo` 引入登记到 tech/02（已在"系统能力"表中）。

## 4. 任务步骤

1. 实现 `platform/inject/` trait：`type_text` / `paste_via_clipboard` / `has_input_focus` / `clipboard_backup` / `clipboard_restore`；三平台实现（Windows SendInput、macOS CGEvent、Linux X11 XTest；Wayland 本阶段标注受限）；
2. 实现 InjectService 降级链：焦点检测 → 模拟键入 →（失败 / 兼容清单命中）→ 剪贴板粘贴（备份原剪贴板 → 写入 → 模拟粘贴 → 恢复原内容）→（无焦点）→ 复制 + 通知；
3. 硬约束：`type_text` 实现中过滤 / 拒绝 `\n` 以外的控制字符注入？——按 PRD，换行属于文本内容允许，**回车执行键（单独 Enter 按键事件）不在本服务暴露**；代码评审把关；
4. 权限缺失（macOS 辅助功能）：降级到剪贴板路径并提示引导；
5. `inject_text` 命令与前端 `api` 封装（供 T-012 联调）；
6. 单元测试：降级链决策逻辑（mock platform）；剪贴板备份恢复的正确性。

## 5. 验收标准

- [ ] 在记事本 / TextEdit / gedit 中：调用 `inject_text` 文本出现在光标处；
- [ ] 在 VS Code、终端（Windows Terminal / iTerm2 / GNOME Terminal）中上屏正确；
- [ ] 无输入焦点时（桌面空白处点击后触发）：文本进入剪贴板且弹出系统通知；
- [ ] 剪贴板路径执行后，原剪贴板内容恢复；
- [ ] 任何调用路径下不产生 Enter 按键事件（测试断言 + 代码评审确认）；
- [ ] macOS 未授权辅助功能时：自动走剪贴板路径并提示授权引导，不崩溃；
- [ ] 三平台手动验证通过。
