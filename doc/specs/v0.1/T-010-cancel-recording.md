## 1. 目标与范围

### 1.1 目标

实现录音的取消能力：用户在录音中可随时取消，已采集音频立即丢弃，不进入识别与上屏。

### 1.2 范围内

- 取消入口：Esc 快捷键（录音期间生效）、悬浮球取消区（T-008 已留接口）、小窗取消按钮（T-009 已留接口）；
- 取消语义：状态机 Recording → Cancelled → Idle；音频缓冲丢弃；不触发识别；
- 已进入 Processing（识别中）后的取消：允许，识别结果丢弃不上屏（竞态处理：上屏前最后检查状态）；
- 取消反馈：悬浮球 / 小窗短暂"已取消"提示。

### 1.3 范围外

- 上屏后的撤回（v0.5 评估）；
- 移动端取消（v1.0，协议 `cancel_record` 已预留）。

## 2. 需求依据

- F-INPUT-07：取消录音（PRD 3.1 节交互与异常）；
- 产品原则 3（结果可预期：可撤回）；
- [tech/05](../../tech/05-core-pipeline.md) 5.2 状态机（Cancelled 迁移）。

## 3. 技术上下文

- 修改：AudioService 状态机（T-005）、AsrService 消费端（T-006）、InjectService 调用点（T-012 串联前的命令层）；
- Esc 捕获：录音期间注册临时应用级快捷键 / 窗口级按键监听（悬浮球不抢焦点，Esc 须全局捕获——复用 T-004 global-shortcut 临时注册）。

## 4. 任务步骤

1. AudioService 增加 `Cancel` 命令处理：丢弃缓冲、状态迁移、广播 `recording:state { Cancelled }`；
2. 录音期间动态注册 Esc 全局快捷键，录音结束 / 取消后注销（避免常驻占用 Esc）；
3. 识别中取消：AsrService 结果回调处检查会话代次（generation counter），过期结果丢弃；
4. 上屏前检查：InjectService 调用前再次确认会话有效；
5. 前端：悬浮球 / 小窗响应 Cancelled 状态显示"已取消"反馈；
6. 单元测试：取消后缓冲为空、代次过期结果丢弃、Esc 注册 / 注销配对。

## 5. 验收标准

- [ ] 录音中按 Esc：录音停止，悬浮球显示已取消，无任何文本上屏；
- [ ] 录音中点悬浮球取消区 / 小窗取消按钮：同上；
- [ ] 识别进行中取消：结果不上屏；
- [ ] 取消后 Esc 快捷键注销（不影响其他应用正常使用 Esc）；
- [ ] 取消后音频缓冲确认丢弃（测试断言）；
- [ ] 三平台手动验证通过。

## 6. 测试要求

- `cargo test`：取消路径、代次机制；
- 手动验证：三个取消入口、识别中取消的竞态（快速取消）。

## 7. 完成定义（DoD）

- 验收标准全部勾选；
