## 1. 目标与范围

### 1.1 目标

实现跨平台麦克风采集服务（AudioService）：设备枚举与选择、常驻预热、录音会话管理、音量电平输出，消费 T-004 的录音控制命令。

### 1.2 范围内

- 基于 `cpal` 的 `platform/audio/` 适配层：设备枚举、默认设备、流打开 / 关闭、热插拔刷新；
- AudioService（actor 模式）：状态机 `Idle / Warming / Recording`，消费 `RecordCommand`；
- 采样参数：16 kHz / 单声道 / f32（设备不支持时重采样）；
- 常驻预热模式（可配，默认开）：设备常开、流常读，非录音状态**丢弃所有采样**（NFR-PR-07）；
- 录音缓冲：录音期间帧入内存缓冲（上限 5 分钟），结束后交给调用方（本任务通过事件 / 回调暴露，T-006 消费）；
- 音量电平：RMS 计算，50 ms 节流广播 `recording:level`；
- 麦克风异常（拔出 / 独占失败）：状态回退 Idle + 明确提示（NFR-R-03）。

### 1.3 范围外

- ASR 识别（T-006）；
- 悬浮球 / 小窗 UI（T-008 / T-009）；
- 移动设备作为音频源（v1.0 T-1014）；
- 录音环境设置页 UI（T-013）。

## 2. 需求依据

- NFR-P-01：预热模式启动延迟 ≤150 ms；NFR-P-02：非预热 ≤500 ms；
- NFR-PR-07：预热状态不得采集或保存声音；
- NFR-R-03：麦克风异常明确提示；
- [tech/04](../../tech/04-backend.md) 4.2 通道设计、4.4 AudioService；
- [tech/05](../../tech/05-core-pipeline.md) 5.2 状态机、5.3.2 采集设计。

## 4. 任务步骤

1. 实现 `platform/audio/` trait（`list_devices` / `open_stream` / 帧回调），三平台 cpal 实现；
2. 定义 `AudioFrame`、录音状态机、`AudioService` actor（mpsc 命令 + 内部状态）；
3. 实现预热：启动时按配置打开设备流，非录音状态采样直接丢弃（代码路径上无缓冲、无写盘）；
4. 实现录音会话：Start → 缓冲帧；Stop → 缓冲打包发出（事件 `recording:audio_ready` 携带帧数据句柄）；Cancel → 丢弃缓冲；
5. RMS 电平计算与 50 ms 节流广播；
6. 设备异常处理：流错误 / 断开 → 状态回退 + `recording:result { Failed, E-AUDIO-xxx }`；
7. 性能埋点：Start 到首帧的耗时日志（验证 NFR-P-01/02）；
8. 单元测试：状态机迁移（用假帧源驱动）；预热丢弃路径的代码审查级验证（测试断言缓冲为空）。

## 5. 验收标准

- [ ] 设备枚举列出系统麦克风，可切换输入设备；
- [ ] 预热模式：按下快捷键（T-004 联调）到首帧采集 ≤150 ms；非预热 ≤500 ms（日志埋点实测）；
- [ ] 预热非录音状态：内存中无音频缓冲累积（测试断言），磁盘无任何音频文件；
- [ ] 录音 5 分钟上限自动结束并发出已采集音频；
- [ ] 录音中拔出麦克风：状态回退 Idle，前端收到带错误编号的失败事件；
- [ ] `recording:level` 事件约 50 ms 间隔、数值随音量变化；
- [ ] 三平台手动验证：采集正常、电平正常、热插拔恢复正常。
