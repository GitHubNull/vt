# 第 7 章 移动麦克风（桌面端配套）

> 本章定义移动麦克风能力的**桌面端**技术设计与双端通信协议。
> 需求依据：F-MIC-01 ~ F-MIC-07；NFR-S-08/09。落地版本：v1.0（F-MIC-05 虚拟麦克风为 v1.x）。
>
> **边界声明**：移动客户端为独立 Git 子项目 `vt-mobile`，**仅支持 Android**（iOS 暂缓，产品决策 2026-10-09）。本章只定义协议与桌面端行为；Android 端的实现文档与任务 SPEC 在 vt-mobile 仓库编写，不在本仓库。

## 7.1 架构总览

```
Android 客户端（vt-mobile）                VT 桌面端（本仓库）
┌──────────────────┐   扫码/mDNS/手动码   ┌───────────────────────────┐
│ 录音 + 控制键面板  │ ◄─────────────────► │ DeviceHub                 │
│ (识别不在移动端)   │   WebSocket 加密通道  │  ├─ PairingManager（配对）  │
└──────────────────┘   （仅局域网/USB）    │  ├─ MdnsBroadcaster       │
                                           │  ├─ WsServer              │
                                           │  ├─ DeviceRegistry       │
                                           │  └─ ControlKeyRouter     │
                                           └───────┬─────────────────┘
                                                   ▼
                                     AudioService（作为虚拟麦克风源）
                                     InjectService（控制键 → 按键注入）
```

- 移动端是纯麦克风 + 遥控器：**识别始终发生在桌面端**（NFR-PR-01 隐私承诺不变）；
- 已连接设备在桌面端"选择麦克风"中呈现为可选输入源，与物理麦克风统一调度；
- 同一时刻只允许一台设备处于"录音输入"状态（先按先得）。

## 7.2 配对（F-MIC-01/02/03）

### 7.2.1 PairingManager

- 配对码：`rand` 生成 6 位数字 + 一次性会话令牌；**有效期 2 分钟**，过期自动刷新（PRD 3.14 节）；
- 二维码：`qrcode` crate 生成 PNG → `image` 缩放 → `base64` 编码 → 前端展示；载荷为 JSON：`{ v, addr, port, code, token_hint }`；
- 配对成功后签发**长期令牌**（`rand` 32 字节），桌面端存 OS 凭据管理器（NFR-S-01），移动端自行保存；之后自动重连凭长期令牌，无需重新配对；
- 配对仅在局域网 / USB 通道内完成，不经过任何云端。

### 7.2.2 三种入口

| 方式 | 桌面端行为 |
| --- | --- |
| 扫码配对（默认） | 设置页"添加设备"展示二维码 + 配对码，等待移动端发起校验 |
| mDNS 发现 | `mdns-sd` 广播服务 `_vibetype._tcp.local.`（含端口与设备名）；移动端发现的桌面端列表来源于此；移动端发起连接时桌面端弹确认框 |
| 手动连接码（兜底） | 设置页展示 6 位一次性码，移动端手动输入 |

### 7.2.3 安全规则（NFR-S-08）

- 未配对设备尝试连接：桌面端弹确认框，拒绝则忽略并记录；同一来源连续 3 次被拒，10 分钟内不再提示；
- 设置项：仅允许已配对设备（默认开）、新设备连接须确认（默认开）、传输加密（默认开，不可关闭）；
- 已配对设备可随时解除配对（立即吊销长期令牌）。

## 7.3 WebSocket 通道（F-MIC-04/07）

### 7.3.1 WsServer

- `tokio-tungstenite` 在局域网接口上监听（端口可配，默认自动选择并写入 mDNS 广播）；
- 每条连接握手后首条消息必须为认证帧（长期令牌或一次性配对码），失败即关闭并记录；
- 传输加密：通道层加密（默认开不可关）；密钥协商在配对 / 认证帧中完成，实现细节在 v1.0 任务 SPEC 中定稿；
- 心跳：5 s 间隔，15 s 无心跳判定断连。

### 7.3.2 消息协议（JSON 控制帧 + 二进制音频帧）

控制帧（`{ type, ... }`）：

| type | 方向 | 说明 |
| --- | --- | --- |
| `auth` | 移动→桌面 | 认证帧（令牌 / 配对码） |
| `auth_result` | 桌面→移动 | 认证结果与桌面端信息 |
| `start_record` / `stop_record` / `cancel_record` | 移动→桌面 | 录音控制（等同桌面快捷键） |
| `audio`（二进制帧） | 移动→桌面 | 音频数据（16 kHz 单声道，编码格式在协议定稿时确定） |
| `control_key` | 移动→桌面 | 控制键事件（见 7.4） |
| `state_sync` | 桌面→移动 | 桌面端状态（场景、激活模板、录音状态） |
| `result_notify` | 桌面→移动 | 上屏成功 / 降级 / 失败（移动端震动 + 文字提示） |
| `battery` / `heartbeat` | 双向 | 电量上报 / 心跳 |

- 断连期间移动端按下的控制键**不缓存、不补发**（NFR-S-09）；
- 录音中断连：桌面端立即结束录音，已采集部分照常识别上屏，双端提示，移动端自动重连（PRD 3.14 异常与边界）。

## 7.4 控制键路由（F-MIC-07）

- ControlKeyRouter 收到 `control_key` 帧 → 校验当前布局与场景 → 转为 InjectService 的按键注入；
- 生效目标 = 桌面端当前焦点窗口（录音开始时锁定的窗口）；
- 布局方案（AI 对话 / 编码 / 终端三套内置 + 自定义）存桌面端配置，同步给移动端渲染；终端布局**不提供回车键**，用户手动添加回车时桌面端执行前弹一次确认（与终端安全保护 NFR-S-05 一致）；
- 桌面端无焦点时收到控制键：不执行，回 `result_notify` 提示"电脑上没有可操作的窗口"；
- 布局导入导出与桌面端备份文件互通（zip 打包）。

## 7.5 桌面端 UI 配套

- "通用 › 录音环境"新增"移动麦克风"卡片 + "管理设备"按钮；托盘菜单"连接手机"入口；
- 设备管理页：已配对设备列表（设备名、连接方式、状态、信号与延迟、重命名、解除配对）；
- 设备状态实时推送：DeviceHub 状态变更 → `device:changed` 事件 → 前端 `useDeviceStore`；
- 低电量（<15%）设备在列表显示低电量标记。

## 7.6 虚拟麦克风（F-MIC-05，v1.x）

把移动设备音频呈现为系统级虚拟麦克风设备，供任意应用使用。平台差异大（Windows 虚拟音频驱动 / macOS CoreAudio 插件 / Linux PipeWire 虚拟源），v1.x 单独立项设计，本章不展开。
