# 第 8 章 数据存储与安全

> 本章描述 VT 的数据目录布局、配置持久化、密钥保管、日志脱敏与敏感信息检测的技术落地。
> 需求依据：NFR-PR-01 ~ 08（隐私）、NFR-S-01 ~ 09（安全）、NFR-R-05（配置原子性）、F-SET-04、F-ME-02、F-ABOUT-02。

## 8.1 数据目录布局

使用 Tauri 的 `path` API 获取平台标准目录，不在安装目录写数据：

| 目录 | 平台路径（示例） | 内容 |
| --- | --- | --- |
| 配置目录 | `~/.config/vibetype/`（Linux）等 | `config.json`、`templates.json`、`dict/`、`layouts/`（控制键布局） |
| 数据目录 | `~/.local/share/vibetype/` 等 | `models/`（ASR 模型）、`stats/`（使用统计）、`cache/`（图标缓存 zip 等） |
| 日志目录 | `~/.local/state/vibetype/logs/` 等 | 按天滚动日志，保留 7 天 |

原则：

- 录音数据**默认不持久化**（NFR-PR-02）：音频帧只在内存缓冲，识别后即弃；历史记录（F-INPUT-08，v1.0）只存识别文本，且可一键清除；
- 一键清除入口（F-SET-04，NFR-PR-05）：删除数据目录下用户内容（历史、统计、缓存），保留配置；
- 卸载时提示是否删除本地数据（NFR-PR-08），由安装器脚本实现（见 [第 9 章](./09-cross-platform.md)）。

## 8.2 配置持久化（ConfigStore）

- 格式：JSON（serde_json），按模块分节；
- **原子写入**（NFR-R-05）：序列化 → 写 `config.json.tmp` → `fsync` → `rename` 覆盖；任何时刻磁盘上不存在半写状态；
- **损坏回退**：读取时 JSON 解析失败 → 尝试 `config.json.bak`（上次良好副本）→ 仍失败则用默认配置启动并提示用户；
- 变更广播：写盘成功后 `config:changed` 事件同步所有窗口；
- 并发：配置读写全部经过 ConfigStore 单例（`RwLock`），前端多窗口不直接碰文件。

## 8.3 密钥与令牌保管（NFR-S-01）

| 秘密 | 存储位置 | 说明 |
| --- | --- | --- |
| AI 供应商 API Key | OS 凭据管理器（`keyring`） | 配置文件只存引用键（如 `cred:provider:deepseek`） |
| MCP 服务令牌 | OS 凭据管理器 | 开启服务时生成 |
| 移动设备长期令牌 | OS 凭据管理器 | 每设备一条 |

- OS 凭据管理器不可用时（部分 Linux 无 Secret Service）：降级为机器绑定的对称加密文件（密钥派生自机器标识），并在设置页明示保护级别；
- 界面一律掩码显示（`sk-****…****`），复制操作需二次确认；
- **任何密钥、令牌不得写入日志、备份（未选含密钥时）、导出文件**（NFR-S-02）。

## 8.4 日志与脱敏（NFR-S-02）

- `tracing` 按天滚动，保留 7 天；导出日志（F-ABOUT-02）含 OS 版本、产品版本、模型信息、最近 1000 行；
- **全局脱敏层**：自定义 `tracing` Layer，在事件写入前对 message 与字段做正则过滤：
  - API Key / 令牌模式（各供应商密钥格式、私钥头尾标记）；
  - 识别文本、提示词内容、选中文本、剪贴板内容（这些字段在代码中就不允许作为日志字段，评审把关）；
- 日志中允许出现：错误编号、状态迁移、耗时数值、设备名（用户自命名除外，脱敏为设备 ID 哈希）。

## 8.5 敏感信息检测（NFR-S-03，v1.0）

- 触发点：AI 外发前（第 6 章隐私闸门）、备份导出时提示；
- 检测在本地完成，规则库内置：云服务 / 大模型密钥格式、私钥、密码赋值、手机号、身份证、银行卡、邮箱、内网地址；
- 命中后自动打码并提示用户确认；检测规则可随版本更新扩充。

## 8.6 导入文件校验（NFR-S-07）

- 词典 / 模板 / 备份 / 布局文件导入时：格式校验（JSON Schema）→ 版本兼容检查 → 条目数量与长度上限；
- 校验失败：拒绝导入并给出原因，**不得导致崩溃或执行文件内任何内容**；
- zip 格式备份包：解包时限制条目数与总大小（防 zip bomb），不解压到临时目录以外。

## 8.7 备份与恢复（F-ME-02，v1.0）

- 备份 = zip 打包配置目录（可选是否含密钥引用——**不含密钥本体**；含密钥选项导出的是 OS 凭据的加密导出，导入时需原机器或用户密码）；
- 恢复走 8.6 的校验流程；恢复前自动备份当前配置。

## 8.8 更新与签名（NFR-S-06）

- 更新检查（F-ABOUT-01）只发送：当前版本号、OS 类型、架构（NFR-PR-06）；
- 更新包下载后校验签名（Tauri Updater 公钥机制），校验失败不得安装；
- 更新服务器地址为项目官方域名，配置中不可被普通设置项修改。

## 8.9 隐私检查清单（每个涉及数据的任务 SPEC 须对照）

- [ ] 录音是否只在内存、识别后即弃？
- [ ] 是否有任何用户文本进入日志 / 遥测？
- [ ] 外发（AI / 更新检查）是否最小化且经用户确认？
- [ ] 新增秘密是否走 OS 凭据管理器？
- [ ] 新增文件导入是否有格式校验？
